# T07-L01 三档窗口请求日志复核

## 范围与环境

使用隔离的临时配置和合成 SQLite 数据运行 GPUI，不读取真实账号、密钥或上游服务。数据集共 45 行：43 条代理记录、1 条内置模型记录和 1 条自定义模型记录；每页 20 条，共 3 页。

窗口外框分别为 1100×700、1280×800、1440×900 px；应用客户区高度分别为 670、770、870 px。截图像素尺寸与各外框相符。可访问性树中日志行高为 56 px，表格视口宽度分别为 747、927、1087 px。

## 复核结果

- 三种尺寸均显示第 1/3 页，并成功翻到第 2/3 页再返回第 1/3 页。第 2 页显示另一组记录。
- 1440×900 下内置模型筛选显示第 1/1 页；恢复全部来源后回到第 1/3 页。
- 截图可见长供应商/模型名被省略而未绘制到相邻列；超大 Token、零值、未知值、进行中、失败和部分数据行均有记录。Token 单元格使用两行内容且行高保持 56 px，没有发现互压或跨列绘制。右侧 tok/s 的长值按列宽省略（例如 `2469...`），未溢出到状态列。1100 px 截图需水平浏览右侧字段；端点完整性属于 L02 的专门验收范围。
- 行滚动有两份可用证据：1100×700 的补充探针图 `shots/probe-rows-scroll.png`，以及 1280×800 的主流程图 `shots/size-1280x800-04-rows-scrolled.png`，可见记录行发生变化。1440×900 主流程的 `04-rows-scrolled` 实际移动了外层页面，行列表没有变化，因此 1440 下的内部行滚动未验证。
- 1100×700 的主流程 `04-rows-scrolled` 与 `01-left` 图像一致，也不能作为滚动成功的证据；补充探针图才是该尺寸的行滚动证据。

## 证据索引与限制

每个尺寸的 `01-left`、`02-token-cost`、`03-status` 分别记录表格左侧、Token/费用区域和右侧状态；`05-page2`、`06-back-page1` 记录翻页。1440×900 额外提供 `07-builtin` 和 `08-all-sources-restored`。`gui-steps.json`、AX dump、OCR 和 GUI 日志保留驱动记录；自动生成的 `acceptance-summary.json` / `analysis.json` 有 OCR 误判，本复核结论以截图和 AX 几何记录为准。

1100×700 的 `00-initial` 图片在一次失败的后续尝试中被覆盖成 1440×901，且其 OCR/AX 文件随之失配；该组三个文件已从证据中删除，不计入验收。失败尝试日志 `logs/gui-run-row-scroll-fix.log` 留存。Codex 环境无法通过辅助功能接口控制该进程，且本地合成 Core 在复跑期间退出，因此没有取得 1440×900 内部行滚动的补充截图。没有产品源码改动。
