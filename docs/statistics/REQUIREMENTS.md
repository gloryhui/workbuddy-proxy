# 使用统计详细需求

版本：设计 v2；日期：2026-10-15。实现顺序以 [开发文档](DEVELOPMENT.md) 和 [推进 Prompt](IMPLEMENTATION-PROMPT.md) 为准。

## 1. 产品目标与范围

让用户回答：我在什么时间、通过哪个供应商配置、使用哪个模型、发起多少请求、输入/输出/缓存各用了多少 Token、哪些请求失败或用量缺失、按配置价格估算多少费用。

目标是本机单用户 WorkBuddy Proxy 的原生统计页，不建设远程计费平台。只统计本代理实际采集的请求。没有旧明细的历史不能恢复；导入 Aiotto/Codex 会话、跨设备同步、多用户权限、账单对账和真实扣费获取不在第一版范围。

### 1.1 交付优先级

| 级别 | 必须交付的能力 |
| --- | --- |
| P0-A | SQLite 迁移、健康状态、请求开始/结束、SSE/JSON usage、有界异步落库、去重、取消/重启处理 |
| P0-B | 管理 API、统一筛选、总览、趋势、请求明细、供应商/模型汇总、GPUI 原生页面 |
| P1（本设计的完整交付范围） | 可修改的当前价格、逐调用单价与费用快照、定价 UI、保留策略、暂停采集、手动清理 |
| P2（明确后置） | CSV 导出、会话统计、P95 延迟、真实账单、自动拉取价格、持久化预聚合、按 API Key/客户端归属、请求正文归档 |

“完成统计功能”须完成 P0-A、P0-B、P1；可以先提交可工作的 P0 切片，但不得把 P1 标为已完成。

## 2. 数据保存原则

1. 每次可识别路由的已接纳请求保存一条摘要，按内部 request_id 唯一，不把每个 SSE chunk 当成请求。
2. 保存时间、路由和模型、用量、状态和耗时；不保存聊天内容、messages、tools、图片、Key、请求/响应原文。
3. provider_id 和 route_id 是稳定维度；显示名称保存当时快照。配置更名、模型下架、供应商删除后历史仍可查看。
4. requested_model 是客户端给代理的模型/别名；upstream_model 是实际发往供应商的模型 ID；response_model 是响应声明，可为空，不能保证揭示供应商内部实际模型。
5. source=relay 是普通转发，source=connection_test 是项目“测试连接”；默认页面排除测试，支持显式包含。
6. 鉴权失败、Host/Origin 拒绝、未拿到并发许可、请求过大、模型无法解析/路由等发生在统计接纳点之前，不写逐请求记录；健康区可以展示本轮聚合拒绝数。页面“请求数”不能标成“所有 HTTP 流量”。
7. 已解析有效路由后发现 Key 缺失，记录 rejected/not_applicable，upstream_started=false。网络失败、上游非 2xx、流内 error、客户端取消均有请求明细。
8. 不对远端模型进行额外探测以补统计，不为了获得 usage 在用户取消后继续读流。
9. 现有“测试连接”首个有效流事件就成功返回并提前停止流，保留此行为。统计中该测试流可为cancelled/missing，文案“探测提前结束”；不把它误判成连接测试失败，不为了末尾usage延长探测。

## 3. 统计口径（前后端、SQL、测试必须一致）

### 3.1 请求与状态

所有图表按 **请求开始时间 started_at_ms** 归属时间段，跨日结束不移到第二天。输入时间统一 UTC 毫秒，筛选范围采用 `[from_ms,to_ms)`。

| 指标 | 定义 |
| --- | --- |
| 请求数 | 筛选范围内已入库的 usage_requests 行数，包含进行中、失败与本地路由后拒绝 |
| 已结束数 | outcome != in_flight |
| 成功数 | outcome=completed；2xx 且协议正常结束，无流错误 |
| 失败数 | outcome=failed 或 rejected；包含本地缺 Key，但另外展示 rejected 子计数 |
| 取消数 | outcome=cancelled |
| 中断数 | outcome=interrupted，含核心异常退出恢复 |
| 成功率 | completed / 已结束数；分母 0 显示“—” |
| 进行中 | outcome=in_flight，单列；不能计为成功 |

HTTP 200 不代表流完整成功。流中断、SSE error、异常 EOF 可以保留 http_status=200，同时 outcome 为 failed/interrupted。UI 同时显示状态码和最终状态。

### 3.2 Token

| 指标 | 口径 |
| --- | --- |
| 输入 Token | 已结束且 usage_status=complete 的 input_tokens 之和，含适配器认定属于输入的缓存 Token |
| 输出 Token | 同范围 output_tokens 之和；思考 Token 如属其子集，不额外加总 |
| 总 Token | 输入 + 输出；缓存读取、缓存创建、思考不再加一次 |
| 缓存读取 | 只累加完整 usage 中实际提供的 cache_read_tokens；同时展示已提供字段的请求覆盖数 |
| 缓存创建 | 同上，缺字段不解释成 0 |
| 新增输入 | 只在输入拆分被证明为 disjoint 时展示 input_uncached_tokens；覆盖不足提示“仅已知拆分” |
| 缓存命中率 | 已知缓存读取的完整请求中，sum(cache_read_tokens) / sum(input_tokens)；分母为这些同一批请求的输入 |
| 完整用量覆盖率 | 已结束且 upstream_started=true 中 complete 的请求数 / 同条件请求数 |

数字为 0 是真实的已报告零；NULL 是未知。若没有任何完整用量，请求数仍正常，Token 卡显示“—”，附“暂无完整用量”，不能显示“已使用 0”。有部分完整用量时显示已确认合计和覆盖率，例如“1.23M · 8/10 请求用量完整”。

usage 状态：

- complete：输入、输出、总数有效且一致；缓存/思考等可选字段允许未知。
- partial：只收到部分已验证字段；保留明细，第一版不加入主 Token 总览。
- missing：没有获得用量；详细原因区分没有 usage、取消、超限、编码不支持等。
- invalid：负数、非整数、溢出、总分不一致或冲突 usage 等，排除主统计。
- not_applicable：明确没有发上游的请求，用量不适用；不计入完整用量覆盖率分母。

即使 outcome=cancelled/failed，只要已获得完整可信 usage，也计入用量，因为可能已发生消耗。完整 usage 不等于请求成功。

### 3.3 性能

- duration_ms：核心从统计接纳到结束/取消的单调时钟耗时；不使用两个墙钟时间相减测延迟。
- ttfb_ms：发起上游到收到上游首个正文字节；不是收到响应头的时间。
- first_content_ms：发起上游到首个可辨识文本、思考、refusal 或工具参数增量；role-only、心跳、空 delta 和 usage-only 不算。UI 标签为“首内容”，不宣称测得模型内部首 Token。
- 非流式请求首内容未知；压缩或无法识别协议时首内容未知，仍可记录 TTFB。
- 平均耗时只使用 outcome=completed、duration_ms 非空的行。重启恢复不能构造 duration_ms=0。
- 第一版不展示吞吐速度和 P95，避免把墙钟/含思考输出混成不可靠的生成速度。

### 3.4 单价快照与估算费用（按用户最新要求修订）

详细规则以[价格设计修订](PRICING-DECISION.md)为准。价格表只保存“供应商配置+上游模型”的当前单价，可以直接新增、修改、删除，不受历史引用限制，不维护生效区间。

每次调用接纳时冻结四项单价、币种、计价模式、来源和时间，终结后独立保存各项费用与本次总金额。历史详情和汇总只读请求自身的价格/费用快照，不依赖当前价格表。

找不到模型价格时四项单价默认0、本次总金额0，显示“0元（未配置价格，按0计算）”；以后补价不改变这条历史记录。Token未知仍为NULL。默认币种来自采集设置default_currency（初始CNY，可设USD），每次调用也冻结该币种。

flat/read_discount/disjoint计算方式、i128纳单位定点及分币种汇总保持。手动非零价格下缺必需用量/拆分仍为金额未知，不能与缺价格默认0混淆。移除“按当前价格重算历史”入口；调价只影响新接纳调用。

## 4. 页面信息架构

采用 Aiotto 截图的信息层次，沿用本项目青蓝色 GPUI 主题和原生组件。一级导航增加“模型管理 / 使用统计”。进入统计页不改变当前供应商选择，也不保存未保存的模型草稿。

### 4.1 页面从上到下

1. 标题“使用统计”：说明“统计本代理已记录的模型请求”，右侧数据库健康与最后刷新时间。
2. 筛选条：供应商、模型、状态、用量完整性、包含测试开关、时间范围、自动刷新、刷新按钮。
3. 数据质量提示：未报告用量、流中断、采集丢弃/数据库故障、暂停采集、保留范围各自有清晰说明。
4. 总览卡：已确认总 Token 为主，次级卡为请求数、成功率、输入、输出、缓存读取/创建、缓存命中率、估算费用。
5. 趋势卡：Token 趋势为主图，下方独立费用图（含缺价默认0）；并列显示覆盖率，不将 Token 与货币放同一轴。
6. 明细卡：页签“请求日志 / 供应商统计 / 模型统计”。页签共用上方筛选条件。
7. 底部折叠区：“成本定价”“采集与存储”；P1 阶段交付对应编辑界面。

截图中的“会话数”“全部客户端”“真实消耗”暂不照搬。本项目没有可靠全量会话/客户端标识，主卡称“已确认 Token”。

### 4.2 筛选交互

- 默认最近 30 个本地日历日（含今天至当前时间），供应商/模型/状态/用量均为全部，排除测试，自动刷新关闭。
- 预设今天、近 7 天、近 30 天、近 90 天和自定义。第一版单次范围最长 366 天；超限说明并要求缩小范围。
- 供应商按稳定 ID 筛选；模型按 upstream_model 精确匹配。删除的供应商仍从历史数据中提供选项，标注“历史配置”。
- 改筛选后等待 250ms 合并请求；请求 generation 递增，过期回复直接丢弃。
- 手动刷新保留筛选、页签、图例和滚动位置；请求列表重置到第一页须有一致规则：筛选变化重置，普通刷新保留当前页。
- 自动刷新选项：关闭/10 秒/30 秒/60 秒，只在统计页可见且窗口前台时执行；上次未结束不叠加请求。
- 换页只刷新表格；图例开关只本地重绘。切页签只取对应汇总或列表，不重复保存配置。
- loading 时保留旧内容加局部进度，不整页闪白。失败保留旧数据，标注“数据更新失败/上次更新时间”。

### 4.3 请求日志

列：时间、供应商/模型、请求标识、Token、估算费用、性能、状态。

- 默认每页 20，支持 20/50/100；服务端分页，按 `(started_at_ms DESC,id DESC)` 固定排序。
- 模型单元格两行：模型 ID + 供应商；hover/详情展示 requested/upstream/response 模型和当时路由名称。
- Token 单元格展示输入↓、输出↑、缓存读、总数Σ；NULL 显示“—”，partial/invalid 旁有状态标签。
- 费用为按币种格式化估值；缺价显示0金额及默认来源；缺用量但有非零单价显示“用量不全”；未发上游显示0与不适用。
- 性能两行：总耗时 + 首内容；TTFB 放详情。未知显示“—”。
- 状态显示 HTTP 码 + completed/failed/cancelled/interrupted 等文字；不可只靠红绿区分。
- 点击行打开原生详情对话框，列出摘要字段、usage 原因、本次单价快照、分项金额、总金额及快照时间，不展示或提供正文查看按钮。
- 第一版使用上一页/下一页和当前页码，不承诺任意跳到第 3868 页。游标与历史快照规则见 API。

### 4.4 供应商与模型统计

供应商按 provider_id 聚合；模型按 upstream_model 聚合，允许跨供应商合并，同一模型在多家调用时标明供应商数量。筛选某供应商后模型统计只算其记录。

显示请求数、成功率、输入/输出/总 Token、缓存命中率及覆盖数、完整 usage 数、分币种费用和已结算请求数（含缺价默认0）。默认按已确认总 Token 降序，允许按请求数排序；排序白名单固定。

重名供应商显示短 ID 以区分。更名后的显示取筛选范围内最新一条历史快照，详情说明“按请求时名称保留历史”。

### 4.5 趋势图

- 自动粒度：<=48 小时用小时，<=90 日用日，更长范围用周；最多 400 桶。用户可选支持的粒度，超点数时拒绝而非任意抽掉日期。
- 输入、输出、缓存读、缓存写四条线可独立开关；Token 使用左轴、从零起、统一刻度。缓存线属于输入细分，图例注明“不可相加”。
- 鼠标悬停给出桶起止时间、完整/缺失请求数、精确整数用量、缓存覆盖和分币种费用。
- 桶内没有请求：在健康/采集覆盖可证实时为真实零；采集暂停、采集丢弃/故障时不能宣称零调用，用浅灰背景提示“记录可能不全”。
- 有请求但没有完整 usage：主折线断开，显示空心/警示点；不能以 0 填补。部分已知时展示已知值并标明部分覆盖。
- 使用直线段，避免平滑曲线过冲造成负数或虚假峰值。数据更新不重新播放整张图动画。
- 费用图放在相同时间轴的下方，高 140px；多个币种切换显示，禁止混币相加。不要求第一版实现双 Y 轴。

## 5. GPUI 布局与可访问性

默认窗口维持 1180×780，最小 1100×700。顶部保留项目标题栏；导航约 168px，主内容水平伸缩，外边距 16px、卡片间距 16px、圆角 12px。不能继续把模型管理右侧日志栏挤在统计页面。

- 宽主区 >=1180px：次级指标每行 4 个；否则每行 3 个，允许多行。
- 筛选控件自动换成两行，不横向挤出窗口。
- 页面纵向滚动，趋势主图 260–300px；明细表独立固定高约 400px，使用 DataTable 虚拟行。
- 表格最小内容宽约 1060px，主区不足时表内横向滚动，页面本身不横向滚动。
- 数字右对齐、等宽数字；中文单位万/亿、英文 k/M/B；tooltip 显示原始整数。金额显示至少 4 位小数，小于显示精度时显示 `<0.0001`。
- 表单、按钮、页签、数据质量警告均有中英文字案与 accessibility label；Tab 可导航，Esc 关闭详情，不触发模型编辑快捷键。
- 颜色沿用主题，建议输入蓝、输出绿、缓存读紫、缓存写橙、费用玫红；每种含文字标签。

## 6. 采集、保留和清理

首次升级默认开启摘要采集，供应商 usage_mode 默认 observe。首次页面注明“从升级并启动采集后开始记录”，并说明只有支持 usage 的供应商才有 Token。

供应商设置可开启“请求上游返回用量”；作用于新请求，合并 `stream_options.include_usage=true`，保留其他 stream_options 字段。不支持时提示用户关闭；不自动重试聊天请求。

暂停采集不停止代理，不删除历史；已有统计 Guard 继续完成本次请求，新请求不再接纳统计。恢复从新请求开始，健康区标出采集中断时间。设置保存失败必须回显失败，不能只在 UI 中变更开关。

默认保留 180 天，可选 30/90/180/365 天或永久（0），完整数据库可配置 7–3650 天。P1 UI 显示数据库文件大小、最早记录、当前行数、WAL 状态和保留截止日。

自动清理仅删除早于截止日的已结束请求，每批最多 1000 行，级联删除 cost，保留进行中。不保留已删除数据的汇总；页面总览只覆盖尚存明细。当前价格配置与历史请求清理独立，仍可自由编辑/删除。

手动“清除历史统计”需要页面内明确确认，是用户点击后的破坏性操作。只清除确认时刻以前已结束的请求；保留进行中和新请求，定价/设置不变。执行异步维护任务，有进度和结果；不在 UI 线程 VACUUM。

## 7. 可靠性与性能要求

- 统计故障不得使正常转发失败，不改变 HTTP 状态、原始响应体、取消传播与 4 并发限制。
- 队列、每请求解析缓存、API 响应、列表大小和查询时间都必须有界；不能积压无界输出正文。
- 数据库不可用时显示 degraded 和本轮丢弃数；不宣称“全量、零丢失”。突然断电、进程崩溃和队列丢弃的精度边界必须披露。
- 核心启动数据库迁移失败不覆盖/删除原库，禁用统计并保持代理服务；用户可读到健康错误码。
- 采集已开启但未收到 usage 时仍有请求数、状态和耗时。
- 目标（需要实测，不是本轮结果）：10 万条下默认总览查询 P95 <500ms、分页 <200ms；100 万条下总览 <2s，单次查询 2s 预算；同机 Mock 基准中代理请求 P95 增幅控制在 5% 或 2ms（二者较大者）内。达不到则报告证据再优化，不删统计点掩盖问题。
- UI 打开后能查询，关闭即释放原生界面进程；后台继续记录；无查询时不启动周期性统计全表扫描。

## 8. 验收场景

| 编号 | 输入/操作 | 预期 |
| --- | --- | --- |
| A01 | JSON 返回 input=1000/output=100/cache_read=800 | 总数1100，缓存不额外加，总览与列表一致 |
| A02 | 同一请求 SSE 分成任意 TCP 块，usage 只在末块 | 只产生一条请求，一次最终用量 |
| A03 | 供应商从不返回 usage | 请求正常，Token未知；缺价费用0，有非零手动价则金额未知 |
| A04 | 收到 HTTP 200 后客户端取消，尚无 usage | cancelled/missing，原流立即取消 |
