# 设计与性能边界

## 目标和取舍

项目定位是 WorkBuddy 的个人本机模型代理。用原生界面降低 UI 运行时开销，用单线程 I/O 调度器减少空闲线程，用连接复用减少握手，用限额避免输入和请求队列无界增长。没有绝对最小 RAM 或最高吞吐量承诺。

网络热路径进行本地认证、借用解析顶层 model 与哈希索引选路。每个模型引用一个共享供应商目标，启动或保存配置时预解析 URL 和 Authorization；每次请求只克隆 Arc，不复制 Key、URL 或整个模型目录。通用供应商不解析 messages，不计算会话哈希。默认仅拼接替换 model 字符串值，其他请求字节（顺序、空白、未知字段、数字格式）保持原样；model 已匹配时直接复用 Bytes。只有用户显式配置思考覆盖才重新序列化顶层参数，messages / tools 保留 RawValue。响应流直接返回，不累积完整输出、不解释 SSE。端到端 HTTP 头和状态保留，去除 hop-by-hop 及 Connection 指定的头；请求替换本地 bearer，重新生成 Host / Content-Length。没有响应解压功能。本地接受的 TCP 连接和上游连接均设置 TCP_NODELAY，避免头部与流式数据分开发送时的小包 Nagle 等待。

请求体仍需收集才能识别 model，Go 上游还需在缺少会话头时推断会话；这不是严格端到端输入零拷贝。8 MiB × 4 是逻辑输入预算，**不是进程 RSS 上限**：解析元数据、HTTP / TLS 缓冲、连接、系统框架和分配器另占内存。相同消息前缀和历史改写无法在没有客户端 ID 时完全消除歧义。

## 多连接路由和同步

最多 64 个供应商、合计 256 个模型。供应商保存一个地址和一个 Key，models 数组保存真实 ID、独立别名、显示名称和思考覆盖。全部模型共用一个核心和全局 4 在途配额。每个模型的 `/r/{模型ID}/v1` 锁定该模型；`/r/{供应商ID}/v1` 限定供应商并提供全部模型；全局端点按唯一别名选路。裸模型 ID 多义时拒绝。Go 的模型 ID 用作会话头命名空间。保存供应商 Key 后新请求立即使用新值；已开始的请求完成原始选路，不在流中途切换。

WorkBuddy 同步以全部已保存供应商的模型为单位，写入独立别名、友好名称和独立 URL，去除已删除或改模型的旧项。同步前检查完整批次：已管理项与上次写入快照不一致时拒绝覆盖；同名用户项冲突时拒绝。未管理条目和外层未知字段保留。恢复记录保存原条目和上次写入快照，批量预检通过后再恢复。配置与 WorkBuddy 文件不能跨文件原子提交；写入前保留 WorkBuddy 备份，失败时尽力回滚管理配置，拒绝不确定的覆盖。

v0.1 / v0.2 配置经私有备份迁移；v0.2 按供应商标签、URL 和 Key 分组，保留唯一旧别名、本地 Key 和安装恢复记录。配置持久化不存聊天内容。新版本 UI 不连接旧核心；旧 UI 常驻时提示先退出，只有后台旧核心时自动停止并重新启动。

## 原生界面

Rust 调用一个小型 C / Objective-C 平台适配层。Windows 主线程运行 Win32 消息循环，Mac 主线程运行 AppKit 事件循环，后台核心只有一个 I/O 运行时。界面作为第二个进程启动。Mac 关闭窗口退出界面进程；Windows 关闭 / 最小化隐藏到托盘并保留界面进程，托盘点击或重复启动恢复原窗口；核心的会话缓存和连接继续保持。测试请求在原生工作线程中执行，保持设置窗口响应。UI 通过仅限本机、独立管理令牌保护的控制 API 保存配置、测试连接和处理 WorkBuddy 配置；控制连接禁用代理，绝不把本机管理令牌和 Key 输入发到系统代理。

FFI 字符串所有权由 Rust 分配，平台读取后调用 `wb_free`。FFI 入口捕获 Rust panic，避免 panic 穿越 C 边界。密钥字段不会回填上游 Key。Mac 关闭设置窗口退出界面进程；Windows 保留托盘。托盘 / 菜单栏退出命令停止核心。

## 性能验证方式

`scripts/benchmark.py` 启动独立 mock 上游进程和独立代理子进程，避免 Python 客户端和模拟服务共享 GIL 对 Windows 时序造成干扰。无界面时测量核心 PID；原生界面模式读取实例记录中的核心 PID，并与界面 PID 的 RSS 相加。共享映射页面可能重复计入，因此总量是保守的进程 RSS 和，不是唯一物理内存。Windows 使用 GetProcessMemoryInfo 的 WorkingSetSize，Unix 使用 ps RSS；这些指标存在平台差异，不能直接作为跨平台排行榜。

基准包含：预热 10 次；直接和代理各 200 个小请求，记录 p50 / p95；4 并发、80 个约 1 MiB 请求，每 150 ms 采样 RSS；负载结束后记录进程 RSS。小请求客户端每次重建连接，上游连接由代理复用。mock 禁止保存请求，测试数据不含真实 Key。

短暂峰值可能被采样遗漏；本地 HTTP 不覆盖 TLS 首次握手、真实 provider 速率限制或模型时间。benchmark 输出记录 OS、架构、模式、二进制大小和脚本参数。指标作为可复现实测，不作为实时互联网速度预测。代码或依赖变更后重新测量。

## 发布验证

GitHub Actions 在 Windows、Apple Silicon Mac、Intel Mac、Linux 上进行编译、lint、单元测试、执行实际二进制冒烟测试；Windows 另执行原生窗口模式。自动测试不代替用户在目标机上的人工 UI、WorkBuddy 真正对话和上游真实账号验收。

发布包仅含二进制、许可证、说明和 Windows 诊断启动器。用户配置始终在发布目录外。Git 忽略规则排除密钥文件、构建目录、日志和基准中间文件。
