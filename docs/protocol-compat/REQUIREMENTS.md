# 多协议兼容需求与边界

## 目标

R01：用户能在一个供应商中显式选择 `openai_chat`、`openai_responses`、`anthropic_messages`、`gemini_generate_content`，添加模型并保存、获取模型、测试、同步 WorkBuddy，实际对话走所选上游协议。

R02：WorkBuddy 继续使用既有全局和 scoped Chat Completions 端点、local_key、友好别名及恢复机制。对外不增加 Responses、Messages、Gemini 原生聊天入口。不要求改 WorkBuddy 本身。

R03：现有 `openai_chat` 默认链路保持请求和响应的原字节语义。跨协议链路使用明确转换契约；不得把“跨协议转换”文案套到 Chat 透传，也不能继续向用户承诺跨协议完全无损。

R04：三个适配器均实现流式与非流式、系统提示、普通多轮、用户图片、function tools、工具结果回传、并行和连续工具循环。优先级表示实施顺序，全部属于交付目标，不是可自行删减的范围。

R05：协议、模型能力和供应商品牌分开。模型名包含 Claude/Gemini 不自动切换协议；同一品牌的 OpenAI 兼容端点仍选 `openai_chat`。不能通过失败后换协议探测真实 Key。

R06：统计功能先完成、验收并按用户授权合入，再从合入后的审定提交创建新的协议实施worktree。协议任务必须对接已有统计模块；当前准备目录只写设计，不从缺统计的旧基线开始业务代码。详细门禁见PARALLEL-WORK.md。

R07：所有原生协议请求与Chat请求进入同一统计生命周期/数据库。必要时扩展现有统计事件、DTO和SQL正式迁移，不另建日志库/写线程。字段和失败语义见STATISTICS-INTEGRATION.md。

## 交付层次

| 层次 | 必须交付 | 不能替代它的结果 |
| --- | --- | --- |
| L0 原有兼容 | 默认配置迁移、稳定路由、Chat 原字节回归 | 新适配器能回复文本 |
| L1 基础协议 | 三协议请求、JSON/SSE、错误、取消、资源上限 | 修改 URL 或请求 JSON |
| L2 智能体 | 一轮至少两工具、结果回传、再调用、最后回答 | 仅返回 tool_calls |
| L3 能力一致 | 图片、思考档位、签名/opaque 回放、能力取交集 | UI 打勾或 models.dev 声明 |
| L4 桌面闭环 | 协议下拉、草稿、复制、发现、测试、同步、中英文 | 仅修改 config.json |
| L5 验收 | 独立消费者 Mock、统计与SQL集成、故障测试、现有回归、性能报告 | 自己生成再用同一个函数解析 |
| L6 实机证据 | WorkBuddy 实际对话及真实上游逐协议证据 | 编译、截图或本地 Mock |

没有真实账号/设备时继续完成 L0–L5，L6 标记待用户环境验收，并交付具体步骤。不得因此停止可独立完成的实现，也不得把总体状态标为“已完成真实验收”。

## 必须保持的旧行为

1. 64 供应商、合计 256 模型、全局 4 在途请求、8 MiB 请求体上限。
2. 鉴权 → try_acquire permit → 有界读取 body → 稳定路由；不能为了转换先读未经鉴权的大 body。
3. 同名模型账号隔离、全局歧义拒绝、provider scope、model scope、旧 `wbp-` 和已安装别名兼容。
4. 只替换本地凭据，用户 Key 不进入 WorkBuddy 配置；无日志中的对话/图片/tools/Key；拒绝重定向；保留 loopback/Origin 检查。
5. 用户同步冲突预检、原配置备份、原条目恢复、未知非管理字段保留、已删除路由清理。
6. Chat 默认不解析 messages/SSE，不因新设计额外哈希每轮消息；Go 特殊会话逻辑仍仅在原用途启用。
7. 已开始的请求绑定 immutable 路由快照。修改协议/Key/URL 不改变进行中的上游或用新凭据续接旧流。
8. 流背压与客户端取消传至 reqwest body；permit 在 EOF、错误、Body Drop 都释放。不得后台偷偷读完已取消的输出。
9. 连接测试维持“首个有效 Chat choices 事件即成功并中止探测”，不能等完整生成/usage 或绕开真实适配链。
10. GPUI Kit 固定版本、原生 UI、按需设置进程、单例、草稿、启动项、端口修改与语言逻辑不退化。

## 明确不做

- 不实现 Responses/Anthropic/Gemini 对外原生入口、任意协议双向矩阵或通用透明反向代理。
- 不增加自动重试、自动切 Key、自动模型回退、错误后自动改协议。
- 不实现模型工具执行器。工具仍由 WorkBuddy 执行，代理只翻译声明/调用/结果。
- 不实现 Realtime/WebSocket、Gemini Live、Gemini Interactions、Vertex OAuth、AWS Bedrock、Azure 专用部署寻址/OAuth。
- 不实现 embeddings、独立图片生成、视频音频生成、batch、上传 Files API、供应商托管 web search/code interpreter/MCP。
- 不重新实现统计数据库/价格/统计面板，不复制或合并另一统计任务的未提交文件；允许且必须对已经合入的统计模块做本次协议所需的事件、字段和迁移扩展。
- 不更换 GUI 框架，不升级 GPUI Kit，不顺手重构整个 proxy/config，不加入第二套设置界面。
- 不安装、覆盖用户运行实例，不读真实 Key 发测试，不启停其他 worktree 的进程。
- 不发版、不更版本号、不创建 Release、不推送/合并或提交代码，除非用户另外授权。

## 不允许的实现捷径

- `todo!()`、未用适配器、固定 OK、假模型列表、硬编码测试模型响应、只在 UI 展示协议但 relay 忽略。
- 用 `collect()`/`text()` 收完整 SSE 后伪装流式输出，或把每个 TCP chunk 当成完整 JSON/SSE 事件。
- 对不支持的工具/图片/结构化输出/字段静默丢弃；用自然语言 system 提示模拟原生 tool_calls。
- 根据正文里的工具名匹配结果；同名并行工具调用必须由 ID 区分。
- 把 reasoning/signature 塞进可见 content，凭空造思考签名，或去掉签名后重试来掩盖错误。
- 上游错误/EOF 后伪造 finish_reason=stop 或 `[DONE]`；多输出 candidates/choices 只随意拿一个而不校验。
- 为跨协议转换启用全局 JSON 归一化、全局解压、全局未知字段过滤，破坏旧透传。
- 修改预期输出、跳过失败用例、删回归、加 blanket allow/ignore 来换取绿灯。
- 用“其余类似”“按需实现”“自行优化”替代本任务明确要求的适配器和验收项目。

## 参数与能力失败原则

跨协议采用明确字段白名单及转换表；不具备可证明等价映射的有效参数在上游发请求前返回 400，指出 JSON 路径、协议、错误码，不回显用户内容。不存在的功能不能靠删除参数后请求成功。

可忽略字段必须逐项列在 CONTRACTS.md，且默认值/空值的处理也有测试。新的未知参数默认拒绝。Chat 透传继续保留所有未知字段。

有效 WorkBuddy 能力是“上游/用户配置能力”与“本适配器已实现能力”的交集。手工勾选不能越过硬性未实现边界，UI 应明确说明；不能为省事把所有原生协议能力一律关掉。

## 最终完成标准

`acceptance.json` 全部必测项有可运行测试或明确平台证据；本机可执行项全部通过；三个原生协议都有流/非流工具闭环、取消及安全错误证据；两个 Cargo 工程构建回归；L6 独立标记。交付包含工作树/分支、基线/当前 SHA、完整差异、测试命令和退出码、性能数字、GUI 截图或未验证说明、限制、下一步实机验收步骤。

当前开发模型是 DeepSeek。不得自动把后续 DeepSeek 独立编写的全部代码署名为 Codex。若提交实际包含本次 Codex 编写的任务书等开发文档，应如实按 AGENTS.md 添加且仅添加一次 `Co-authored-by: Codex <codex@openai.com>`，保留真人 Author/Committer。若只提交其他工具独立贡献且来源明确，不伪造 Codex 参与。
