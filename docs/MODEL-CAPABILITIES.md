# 模型能力与多模态转发（v0.5.3）

模型表格点击“操作”列的编辑图标、双击一行，或选中后按 Enter / F2，可编辑该模型的 WorkBuddy 能力声明。默认勾选“自动识别模型能力”，通常无需手动调整；取消后可以独立设置：

| 设置 | WorkBuddy 配置 |
| --- | --- |
| 工具调用、图片输入 | `supportsToolCall`、`supportsImages` |
| 思考模式、仅思考模式 | `supportsReasoning`、`onlyReasoning` |
| 允许关闭思考、默认档位、支持档位 | `reasoning.canDisableThinking`、`defaultEffort`、`supportedEfforts` |
| 输入／输出上限 | `maxInputTokens`、`maxOutputTokens`；留空时不写入限制 |
| 默认／可选上下文长度 | `contextWindow.defaultLength`、`supportedLengths` |
| 自定义协议 | `useCustomProtocol`；同步完整的 `/chat/completions` 地址 |

编辑确认后先保存，再同步 WorkBuddy。手动能力保存在代理配置和私有草稿中，复制供应商、重命名模型、再次同步时保留。旧客户端保存没有能力字段的模型行时也保留现有设置；明确恢复自动模式后才移除覆盖。设置无效时保留原配置，显示错误。

## 自动识别与缓存

参考 [Magpie](https://github.com/yetone/magpie) 的分层目录方式，按字段从低到高补齐：

1. 通用默认及少量内置模型规则。
2. models.dev 中能够唯一确定的原厂模型记录。
3. models.dev 中匹配当前供应商接口的模型记录。
4. 供应商 `/models` 明确返回的能力字段。
5. 用户手动配置；手动模式下使用完整的用户设置，不受自动刷新覆盖。

供应商地址按接口路径隔离，保留套餐分支和本地端口；OpenCode 旧 `/zen/go/v1` 与新 `/inference/go/v1` 可匹配同一 Go 目录，但不会与普通 API 混用。模型先精确匹配，再使用无歧义的命名空间名称；不同原厂同名或多个冲突条目不自动任选其一。原厂 API 使用别名时，只有该原厂指向同一模型且能力一致的别名才可作为回退。

启动和保存后在后台刷新，界面不等待联网。获取模型时同时保存上游明确提供的图片、工具、思考档位、输入／输出及上下文信息；返回给模型选择弹窗的仍是兼容的 ID 列表。手动添加的模型也会在保存及同步时使用同样的解析链路。同步前最多等待 6 秒刷新，然后使用已有缓存；失败不阻止保存、转发或同步。

公共目录访问 `https://models.dev/api.json`，不携带供应商 Key。目录及供应商元数据缓存写入配置目录的 `model-catalog.json`，只含地址、模型能力和更新时间，不含 Key 或请求内容。缓存有效期 24 小时，每小时检查；刷新失败至少间隔 1 小时重试，继续使用最后一次成功数据。文件损坏时安全回退。公共下载上限 16 MiB，供应商列表保持 1 MiB／4096 项限制；后台并行查询最多 2 个供应商。转发路径不读取目录或查询网络。

模型编辑窗口自动显示解析结果和主要来源，图片字段没有明确声明时显示“尚未确认”。自动值不写成手动覆盖：重命名、切换接口或下次更新会重新按当前模型解析，手动模式及草稿仍保留用户设置。公共数据只是能力声明，不能证明当前 Key 的实际权限；普通连接测试也不证明读图或工具调用可用。

图片输入声明用于 WorkBuddy 的附件和读图工具。离线且没有可信缓存时，DeepSeek V4.1 Flash（`deepseek-v4.1-flash`、`deepseek-flash`）仍使用内置图片预设；其他未知模型的图片和思考保持关闭，工具调用沿用通用开启默认。内置规则是最后的回退，不优先于供应商明确声明。

只同步 WorkBuddy 支持的思考档位 `low/medium/high/xhigh/max`，不会把预算值或数值推理强度当作档位。仅有 `reasoning=true`、没有已知档位的未知模型，不虚构可选档位。输入窗口取已知上下文与输入上限中的较小值，输出上限单独声明；自定义协议地址不会由目录自动开启。

这些声明控制 WorkBuddy 的使用方式，不会对请求中的媒体内容做过滤、改写或协议转换。供应商级“思考强度”仍是转发时的参数覆盖；模型能力中的思考选项用于 WorkBuddy 的选择器，两者用途不同。希望 WorkBuddy 自行选择档位时，供应商级设置应使用“跟随 WorkBuddy”。

## 请求与响应边界

- 入口为 OpenAI 兼容 Chat Completions。`messages` 中的文字、图片 URL、Base64 图片，以及上游接受的音频／视频 JSON 字段和工具内容均保留。
- 默认只替换模型别名，其他请求字节保持原样。启用思考覆盖时仍保留媒体和工具字段的原始 JSON 内容。
- SSE 与非流式响应按字节转发，不截取或解释媒体输出。
- 不提供独立的视频生成、文件上传、音频转录等接口，不替 WorkBuddy 拆帧、转码或下载媒体。当前 WorkBuddy 没有独立的音频／视频能力开关；能否发送及识别这些内容，由客户端格式和上游支持决定。
- 请求体上限仍为 **8 MiB**，包含 Base64 膨胀后的媒体、全部历史消息和其他字段；超过上限返回 413。代理不扩充上游权限或模型能力。
- “自定义协议”在当前 WorkBuddy 中表示直接使用完整请求 URL。本代理仍只接受 Chat Completions；开启后同步完整的本地 Chat Completions 地址，不表示支持 Anthropic 或其他协议。

`scripts/model_capabilities_test.py` 使用本机模拟目录和上游，覆盖自动发现、供应商／套餐隔离、能力优先级、手动覆盖／恢复自动、重命名、同步、离线、刷新失败退避和坏缓存恢复。

`scripts/multimodal_test.py` 使用隔离配置和本机模拟上游，验证媒体请求、媒体响应、能力保存／覆盖／恢复自动、同步及取消同步。测试不访问外部媒体，也不证明真实供应商账号支持相关模型或输入格式。
