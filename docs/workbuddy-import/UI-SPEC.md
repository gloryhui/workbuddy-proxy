# 界面布局与交互实施规格 v1.0

## U01. 参考和落地边界

用户提供三张 Aiotto 筛选条截图，分别展示“全部来源 / 官方请求 / 供应商请求”的选中态。采纳**筛选条最左侧三个互斥图标**的结构和识别语义。产品仍为现有 Rust GPUI 桌面界面，不改成 Web，不复制 Aiotto 的大尺寸网页卡片、客户端筛选或整页主题。

本产品确定文案为“全部来源 / 内置模型 / 供应商模型”；第三类包含用户直连自定义模型与 Proxy 模型，不能误做成仅 Proxy。示意图见 [UI-WIREFRAME.svg](UI-WIREFRAME.svg)；合成示例数值不是用户实际数据。本文尺寸单位为逻辑 px，不能按截图物理像素放大两倍。

原左侧导航（数据统计 / 供应商管理）        统计内容列
                                      ① 标题「数据统计」
                                      ② 采集健康条：代理状态 · WorkBuddy 导入状态
                                      ③ 筛选卡片：三个来源图标放最前
                                         ↓ 展开的高级筛选（默认折叠）

                                      ⑥ 使用趋势（沿用原图表）
                                      ⑦ 用量明细 / 供应商统计 / 模型统计
                                      ⑧ 成本定价（沿用，导入伪供应商不可编辑价格）
                                      ⑨ 采集与存储（原设置）

保留默认窗口 1440×900、最小 1100×700，原侧栏、标题栏、语言按钮及总体留白不变。内容纵向滚动；只有明细表允许横向滚动，页面和筛选卡片不能出现横向滚动条。不新增主导航项。

## U04. 第一行控件顺序与宽度

严格按以下顺序：来源图标组 → 供应商 → 模型 → 状态 → 自动刷新周期 → 日期范围 → 刷新按钮 → 更多筛选。

| 控件 | 宽度 | 高度 |
|---|---:|---:|
| 来源组 | 108 | 32 |
| 供应商 | 136 | 32 |
| 模型 | 180 | 32 |
| 状态 | 112 | 32 |
| 自动刷新周期 | 88 | 32 |
| 日期范围 | 168 | 32 |
| 刷新 / 更多 | 各 32 | 32 |

间距 8；筛选卡内边距 12。控件可见文本过长用 ellipsis + tooltip，不挤压来源组。中英文宽度相同；英文标签可缩写，但 accessibility 使用完整文本。日期实际显示与原日期控件一致，默认仍为**当天**；参考图的 30 天/30 秒不是本次修改要求，不改原默认值。

布局按卡片内容可用宽度 A 决定，不按整个窗口宽度猜：

- A≥1012：一行，按上表总宽 1012；剩余空间留右侧。
- 560≤A<1012：强制两行。第一行固定来源/供应商/模型/状态；第二行固定自动刷新/日期/刷新/更多，左对齐，行距 8。
- A<560（系统大字体、极窄内容）：第一行仍保留完整来源组，其他完整控件按顺序 wrap；不得截断来源组、重叠或使用负 margin。

需要抽离布局预算纯函数（宽度→row slots），不要依靠现有 `(filters_width - ...)` 魔数直接减 108 导致英文溢出。不要借此重排侧栏或改变窗口最小尺寸。

## U05. 高级筛选

原高级筛选继续保留供应商搜索、模型搜索、用量完整性、包含测试连接；在最前新增“采集方式 / Capture method”下拉，宽 164，高 32，选项固定“全部 / All”“代理采集 / Proxy”“WorkBuddy 导入 / WorkBuddy import”。高级区上边分隔线和 padding 沿用现有样式。

builtin 来源下该下拉显示“WorkBuddy 导入”且 disabled（请求用 capture_method=all，以来源决定限制）；其他来源可选。切换 builtin 时清除隐藏的 proxy 值；切回来仍 all，不自动恢复隐藏条件。include_tests 只在 all/supplier 且采集方式非 workbuddy 时可用；不可用时清为 false。高级筛选非默认时“更多”按钮保留原蓝色激活提示。

## U06. 筛选联动和防旧响应覆盖

每次来源/采集方式变化，按此顺序：

1. 同步改变选中态及内存筛选模型；立即 invalidates dashboard/rows/groups/filter-options 的旧请求身份。
2. 清空供应商、模型、状态筛选为各自“全部”，保留日期/时区/分页大小/当前 tab/合法的用量完整性条件；分页回第一页。
3. 根据 U05 重置不兼容的高级条件；生成包含两新字段的 filter key。
4. 向原 scheduler 提交一次 dashboard、当前 tab 数据、供应商/模型候选查询；仅替换相同资源的旧 read intent。
5. 新数据到来前旧数字可保留但显示“正在更新…”并降低透明度，不能看起来属于新来源；旧来源 reply 到达完全丢弃（包括错误和 loading 标志）。

更换 tab 仍保留来源。再次点击当前来源不重置分页。页面关闭/重开默认 all/all（第一版不新增筛选持久化）；数据导入启停设置持久化。手动“刷新统计”只查询 SQLite；不隐式发起完整重扫，也不触发 WorkBuddy 同步/重启。

## U07. 健康条、提示条和空态

原代理健康条仍显示原含义；后面以 12px 间距添加 `WorkBuddy：未开启 / 导入中 / 已更新 HH:MM / 已暂停 / 需处理`。只显示静态更新时间，不逐秒刷新文字。全局数据库大小仍包含辅助表，但“记录”计数明确是 usage_requests，不能把 ledger 数量加上。

提示条优先级：导入失败（橙）→待确认/冲突（橙）→未开启/目录不存在（中性）。最多两条，全文可换行；不能用弹窗每 10 秒打扰。

- 未开启：`尚未导入 WorkBuddy 内置及直连模型用量。` 操作 `设置导入` 滚动并展开设置子区，不自动开启。
- 无目录：`未找到本机 WorkBuddy 数据。已有代理统计可正常查看。` 操作 `重新检查`。
- 待确认：`有 N 条历史记录尚未确认来源，未计入总量。` 操作 `查看待确认`。
- 错误：`部分 WorkBuddy 文件暂时无法读取，已导入数据仍可查看。` 操作 `重试`；详情固定原因，无绝对私有路径。
- 有效筛选零记录：`此范围暂无用量记录`；表头/筛选保留，不能把未知总 Token 渲染为 0。

## U08. 指标与趋势

保留大字“Token 总用量”，提示改为“只汇总用量完整的已记录条目”。原 8 个辅助指标顺序保留，修改两个名称，并末尾追加一个：

1. 用量记录（原请求数）：副文案 `代理 X · 导入 Y`。
2. 代理成功率（原成功率）：只按 proxy 状态，纯导入显示 —；副文案 `仅代理请求有状态依据`。
3. 输入 Token；4. 输出 Token；5. 缓存读取；6. 缓存创建。
7. 已记录用量完整率（原完整覆盖率）：不能写“全部调用覆盖率”。
8. 代理估算费用（原估算费用）：沿用 USD/CNY 分开，副文案 `导入费用未知 N 条`。
9. WorkBuddy 点数：credit 独立总计，未知显示 —，已知0显示0，副文案 `日志记录值，不代表账号余额`。

九项在 A≥1000 时每行 5 项（第二行4项），600≤A<1000 时每行3项；小于600每行2项。单项最小宽160，gap12，数值超过宽度用紧凑格式，tooltip 精确整数；金额沿用 i128 字符串 formatter，不引入 unwrap_or(0)。卡片高度自适应，不截字。

趋势图继续输入/输出/缓存/货币费用原序列；同一筛选驱动全部曲线。本期不新增 credit 曲线，不把 credit 混入费用坐标轴。图下注明“导入记录按 WorkBuddy 消息时间分桶”。只有导入且未知货币时隐藏货币线，不能画一条零费用线暗示免费。

## U09. 明细与分组

第一个 tab 从“请求日志”改名“用量明细 / Usage records”；供应商统计、模型统计位置不变。请求表时间列继续固定最左，在其后增加“来源”列（100px，可调最小80），显示标签：`代理 / Proxy`、`内置 / Built-in`、`直连 / Direct`；tooltip 补充采集方式。标签配色与来源语义相同，文字不能省略到只剩颜色。

其余列按原顺序，末尾增加“点数 / Credits”（90px）。缺失耗时/速率/HTTP/费用显示 —；状态 recorded 显示“已记录 / Recorded”，不能用成功绿勾。模型 ID 可以同名但来源不同，不因显示名合并单条记录。供应商分组有 `WorkBuddy` 和 `WorkBuddy 自定义` 合成显示值，模型分组遵循当前合并相同 upstream_model 的规则；来源筛选决定集合，并在行展开/tooltip 标来源构成。

详情弹窗沿用现有容器，在顶部加入来源、采集方式、时间依据（请求开始/消息记录）、“由输入+输出推导总量”标志；导入 HTTP/协议/stream/耗时缺失标未知。credit 单独行，费用与价格快照不出现默认零单价。只展示规范化元数据，不提供“查看原始聊天”按钮。

## U10. WorkBuddy 本地用量子区

位于“采集与存储”内现有设置之后，以顶部分隔线、标题 `WorkBuddy 本地用量 / WorkBuddy local usage` 呈现。原存储折叠行为保留。

固定排列：

- 第一行：左侧开关 `导入本机 WorkBuddy 用量`，右侧按钮 `检查更新`、`完整核对`（高度28，间隔8）。默认关；有扫描时同任务按钮 disabled 并显示静态“处理中”。
- 第二行：简述 `后台增量读取内置与直连模型记录；代理请求自动排除。`。
- 第三行：状态 + 最近增量时间 + 最近完整核对时间；没有完成时间显示 —。
- 第四行：已导入 / 已排除代理 / 待确认 / 冲突 / 跳过异常 / 已清除六个计数，flex wrap，不能固定单行造成溢出。
- 第五行（存在 pending 时）：`查看待确认 (N)` 按钮；存在 conflict 时另有只读错误解释，不提供“全部忽略错误”按钮。

首次开启无需额外确认弹窗：用户点击开关即授权本地导入；后台历史回填立即排队，开关保存失败回滚显示。关闭后历史保留，提示 `已暂停导入，已有统计保留`。全局采集关时保留此开关意图但禁用检查按钮，显示 `全局采集已关闭`。

完整核对只用于按账本去重重扫，tooltip `重新检查全部本地记录，不会恢复已清除条目`；不会清空库或游标。手动检查只跑增量。清除历史原确认对话框增加 `清除已入库记录，保留去重标记；不修改 WorkBuddy 源文件。`，不得增加“同步删除 WorkBuddy 聊天”。

## U11. 历史来源确认弹窗

最宽720、最小520、高度不超过当前窗口80%；内部列表独立滚动，分页20/50/100。列：模型 ID、记录数、最早/最晚时间、原因、操作。仅 pending_classification 可操作；缺身份、数字非法、冲突不可用归属确认绕过。

点操作进入固定表单：只读模型 ID；起止时间（本机时区，终点不含）；互斥选择“用户直连”“通过本 Proxy”；默认不选；预览按钮。预览后显示影响N条和期间，最终按钮 `确认归属`；token过期、revision冲突重新预览，不能默认选择直连。明确代理证据与用户选择冲突时阻止。

历史人工规则列表只列来源manual，有 `撤销` → 预览影响数 → 确认；不能改 verified managed_sync。撤销后显示数据撤回，刷新所有报表并使旧游标失效。

## U12. UI 自动与人工验收

自动验证布局预算边界（A=1012/1011/560/559），source state、按键、重复点击不请求、旧回复丢弃、禁用状态、来源筛选进入所有命令。资产测试证明三个 SVG 匹配三个不同形状，不是统一加号。

必须用隔离配置运行真正打包的 GPUI helper，在 1440×900、1100×700、中文/英文、系统缩放1×/2×下检查。至少留 12 张截图：3来源×2尺寸×2语言；另留展开高级筛选、初始未开启、导入中、待确认、纯导入未知费用/成功率、详情等状态截图。2×验证是平台显示缩放，不能用编辑器把PNG放大冒充。

鼠标切换、键盘切换、滚动、下拉、分页、来源确认/撤销、关闭重开均需要真实事件测试。源码编译、Mock API和静态线框图不能当作 GUI 验收。没有平台机器时标 BLOCKED_EXTERNAL，不能声称验收已过。

## WB-RT-001：同步与展示刷新独立

页面保留“关闭 / 5 / 10 / 30 / 60 秒”及默认关闭，只决定SQLite查询和展示刷新；不新增“实时”选项。导入设置说明改为“每5秒后台增量同步内置与直连模型记录；代理请求自动排除。页面刷新关闭不影响同步。” 不新增同步周期设置。切页、隐藏窗口、关闭页面刷新均不改变后台同步；图中30秒仍是页面刷新示例。
