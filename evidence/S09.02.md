## 交付内容

**布局预算纯函数（U04 的核心要求）**：

```rust
pub fn layout(available: i32) -> FilterLayout
```

`available` 是**卡片自己的可用宽度**（不是窗口宽度），返回值是按行分组的槽位：

| 条件 | 结果 |
|---|---|
| `A ≥ 1012` | 一行，八个槽位按序 |
| `560 ≤ A < 1012` | 两行：`[来源, 供应商, 模型, 状态]` + `[自动刷新, 日期, 刷新, 更多]` |
| `A < 560` | 第一行**只有完整的来源组**，其余按顺序逐行 wrap |

配套：`FilterSlot`（八个槽位，各带规格宽度 108/136/180/112/88/168/32/32）、`GAP=8`、`PADDING=12`、`SINGLE_ROW_WIDTH=1012`、`NARROW_WIDTH=560`。

**去掉魔数**：`statistics.rs` 里原本是

```rust
let extra = (self.filters_width - if self.zh { 268. } else { 332. } - 350.).clamp(0., 140.);
let available = f32::from(bounds.size.width) - 24.;
```

现在改为由 `layout()` 决定"是否单行"、由 `PADDING * 2` 表示卡片内边距 —— 不再从猜出来的宽度里减一个魔数 108/350，这正是英文标签曾经溢出的原因。

**高级采集方式下拉（U05 的呈现部分）**：`CaptureChoice`（`All`/`Proxy`/`WorkbuddyImport`）与 `CaptureFilter`，后者暴露 `is_locked(scope)`（builtin 下锁定）与 `displayed(scope)`（锁定时显示"WorkBuddy 导入"）。两者都成为视图的**真实字段**并参与"高级筛选是否激活"的判断。

## 错误场景证据（真实失败）

实现阶段有三轮真实失败，全部是"新类型没有生产使用点"：

1. **dead_code（布局）**：`FilterSlot`/`GAP`/`PADDING`/`SINGLE_ROW_WIDTH`/`NARROW_WIDTH` 都因 `layout()` 尚未被调用而报未使用。**未加抑制**，改为在 `statistics.rs` 的筛选条渲染中真实调用 `layout()`，并用它决定选择器是否加宽、用 `PADDING * 2` 替换字面量 24。
2. **dead_code（布局辅助方法）**：`first_row`/`starts_with_source`/`source_is_whole`/`row_of` 四个便利方法无人调用 → **删掉它们**，测试直接断言 `rows`（`rows` 才是事实来源，便利方法只是包装）。
3. **dead_code（采集下拉）**：`CaptureFilter` 及其方法无构造点 → 让它成为视图的**真实字段**并参与高级条件判断；同时把冗余的 `choice()` 访问器删掉（`displayed()` 已足够）。

另有一轮 `E0599`：`self.source_scope()` 方法不存在 → 补上（它读的正是 S09.01 的 `SourceFilter`，于是那个组件也第一次成为视图的真实字段）。
