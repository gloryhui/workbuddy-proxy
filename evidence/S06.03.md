## 交付内容

| 项 | 内容 |
|---|---|
| `ReplayOutcome` | `New` / **`Duplicate`**（同语义 hash）/ **`Conflicted`**（不同 hash） |
| `resolve_replay(tx, item, namespace, mapping_revision, now_ms)` | 在 `commit_batch` 内、写任何新行之前解析同键情况 |
| `withdraw_workbuddy_fact(tx, entry_key)` | **先**把 ledger 移出 `imported`（清空 `request_id`），**再**删除 workbuddy 事实行；删除谓词限定 `record_origin IN ('workbuddy_builtin','workbuddy_custom')` |
| `CommitReport.conflicted` | 新增计数 |

判定规则：

- **同 hash → no-op**：只把该条计入 `duplicates`，**不写第二条事实、不改状态、不改 ledger**。这正是"ACK 丢失 / 重复批 / 复制文件 / 重复工具响应都只计一次"的机制 —— 去重键 `SHA256(域 + namespace + sessionId + messageId)`（S03.02）保证这些场景落到同一个 `entry_key`，语义 hash 相同则一律 no-op。
- **不同 hash → 撤回并置 conflict**：撤掉该身份的 workbuddy 明细（事实行删除、ledger 置 `conflict`、`request_id=NULL`），**绝不**把新内容静默覆盖成事实。
- **proxy 决策不被改写**：若已存在行是 `excluded_proxy`，则**完全不动**它 —— 既不撤状态也不写事实，只把该条计为 `conflicted`。导入永远不能删除或覆写代理侧的结论。

## AC043 覆盖（ACK 丢失 / 重复批 / 复制文件 / 重复工具响应）

| 场景 | 用例与断言 |
|---|---|
| **ACK 丢失 + 重复批** | `a_lost_ack_and_a_repeated_batch_count_exactly_once`（首批 `(imported, duplicates, conflicted) = (1,0,0)`；从首批留下的检查点续跑同一批 → `(0,1,0)`；事实行仍 **1**、ledger 仍 **1** 行） |
| **复制文件 + 重复工具响应** | `a_copied_file_and_a_duplicated_tool_response_count_once`（同一身份与内容再次出现 → `duplicates=1`，事实行仍 1） |
| **不同 hash → 撤回 + 冲突** | `a_different_hash_withdraws_the_detail_and_leaves_a_conflict`（`(imported, conflicted) = (0,1)`；workbuddy 事实行由 1 降为 **0**；ledger 为 `Conflict` 且 `request_id=NULL`） |
| **proxy 不被删除/覆写** | `a_proxy_decision_is_never_rewritten_by_an_import`（代理排除行在同键不同 hash 到达后**仍为 `excluded_proxy`**，且全程没有产生事实行） |
| 重放契约 | `the_replay_contract_holds`（启动自检） |
