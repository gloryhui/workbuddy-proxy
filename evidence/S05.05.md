## 交付内容

| 项 | 内容 |
|---|---|
| `SyncHooks` | `prepare()` 与 `finalize()` 两个钩子 |
| `SyncOutcome` | `Confirmed(usize)` / `SyncedUnconfirmed { changed, error }`；`changed()`、`is_confirmed()`、`error_code()`（固定码 `attribution_unconfirmed`） |
| `configure_workbuddy(path, hooks)` | **prepare 在取 config 锁之前、任何文件写入之前**调用；写文件序列不变；`*cfg = next` 之后**先 `drop(cfg)` 再 finalize** |

关键顺序（对应 AC037 的两条要求）：

1. **prepare 失败 ⇒ 零 WorkBuddy 文件变更**：`hooks.prepare()?` 位于函数最前，早于 `self.config.lock()`、`Document::read`、`backup` 与两次 `write_json`。失败时直接返回 `Err`，磁盘上 `models.json` 与 `config.json` 逐字节不变，内存中的连接列表也未被改动。
2. **finalize 失败 ⇒ 报告"已同步但归属未确认"**：写入已经完成，因此返回 `Ok(SyncOutcome::SyncedUnconfirmed { .. })` 而**不是** `Err`；`proxy.rs` 的 `install` 分支据此返回"已同步 N 项配置到文件，但归属未确认（attribution_unconfirmed）"，明确这是**部分状态**而非需要重试的失败。
3. **不跨 await 持 config Mutex**：`configure_workbuddy` 全程同步，`prepare` 在锁外、`finalize` 在 `drop(cfg)` 之后，锁的生命周期内没有任何 `.await`。

## 错误场景证据（真实失败）

`gate.txt` 之前有三轮真实失败，全部是**测试夹具/断言前提**问题，实现逻辑未改：

1. `PathBuf` 未在测试作用域内 → 限定为 `std::path::PathBuf`。
2. `config.json` 在测试夹具中**并不存在**（只有 `models.json` 被创建），`fs::read(...).unwrap()` 报 `NotFound` → 改为比较 `Option<Vec<u8>>`，使"仍然不存在"也成为可断言的状态。
3. 内存断言写死"连接数为 0"，但 `Config::default()` 本身就带有 workbuddy 连接，前提不成立 → 改为**比较调用前后的连接数**（真正的"零变更"语义）。

另有一处编辑事故：插入 `SyncHooks` 时把 `pub fn route` 的 `pub` 与 `fn` 拆开，导致 `visibility pub is not followed by an item`；已按原样恢复签名。
