## 交付内容

`evaluate(line, file_stem, namespace_id, now_ms) -> ParseDisposition` 把整条链路串成一次调用：

| 顺序 | 判定 | 处置 | 诊断计数 |
|---|---|---|---|
| 1 | 非 JSON 对象 / 语法错误 | `JsonSyntaxError` | `json_syntax_error` |
| 2 | 非 usage 类型或角色 | `Ignored` | `ignored` |
| 3 | usage 类型但**完全没有 usage 对象** | `IgnoredNoUsage` | `ignored_no_usage` |
| 4 | 缺 `messageId` | `PendingIdentity` | `pending_identity` |
| 5 | 身份结构性损坏（session 缺失/不符、控制字符、超长） | `Malformed(reason)` | `malformed.*` |
| 6 | 时间戳缺失/非整数/负/超 24h | `InvalidTimestamp` | `invalid_timestamp` |
| 7 | 其余 | `Candidate(Box<Candidate>)` | 无（结果由分类决定） |

顺序理由（写入代码注释与证据）：第 3 步先于第 4 步 —— 一条**既没有 usage 也没有 messageId** 的记录没有任何可导入内容，记 `ignored_no_usage` 比报"缺身份"更准确。

候选装配：`entry_key`/`session_hash`/`message_hash`/`requested_model`/`event_at_ms`/`upstream_model`/`response_model` 来自身份层，`usage` 来自 `normalize_usage` → `normalize_cache_and_reasoning` → `normalize_credit` 三步规则。

**`usage_status=invalid` 与 `missing` 的记录同样形成候选**：它们要以自己的 status/reason 落库（`invalid` 的 Token 列全 `None`），而不是被静默丢弃。

## AC022 覆盖

| 要求 | 用例与断言 |
|---|---|
| 完整记录形成候选 | `a_complete_record_becomes_a_candidate`（`entry_key` 64 hex、`event_at_ms` 等于源时间、`usage` 为 `Complete`、credit 精确） |
| 一次调用跑完整链路 | `the_whole_chain_runs_in_one_call`（Token + 缓存 + 推理 + credit + 上游模型同源） |
| usage 缺失的稳定摘要 | `a_record_without_a_usage_object_is_ignored_no_usage`（含"有 messageId"与"无 messageId"两种，均为 `ignored_no_usage`） |
| 身份缺失的稳定摘要 | `a_usage_bearing_record_without_message_id_is_pending_identity` |
| 非 usage 记录 | `non_usage_records_are_ignored_before_anything_else`（user / reasoning / function_call_result） |
| 非法与缺失仍成候选 | `an_invalid_or_missing_usage_still_becomes_a_candidate`（`-1` → `invalid`+`invalid_numbers`；`rawUsage:{}` → `missing` 且无 Token；坏 credit 只置 `credit_invalid` 而记录仍 `Partial`） |
| 各拒绝路径的独立处置 | `identity_and_time_problems_keep_their_own_dispositions`（session 不符/缺失、非整数时间戳、`{` 与 `[]`） |
| 每个处置恰好一个诊断 | `every_disposition_contributes_exactly_one_diagnostic`（6 类累加后 `total()` 等于用例数；候选的 `diagnostic()` 为 `None`） |
