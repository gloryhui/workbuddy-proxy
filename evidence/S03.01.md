## 交付内容（`parser.rs`）

| 项 | 内容 |
|---|---|
| `NumberLiteral` | `Integer(i64)` / `Other`（存在但不是普通整数）；自定义 `Deserialize` 走 `deserialize_any`，浮点、字符串、布尔、超出 `i64` 一律 `Other`，**绝不做 `as i64` 截断** |
| `NumberText` | 保留 JSON 数字的**原始字面量文本**（经 `RawValue`），供 credit 精确解析；`1e3` 原样保留为 `"1e3"` |
| typed 白名单 | `RawProvider`（`messageId`/`requestModelId`/`requestModelName`/`model`/`responseModelId`/`rawUsage`/`usage`）、`RawUsage`（snake_case，含 `prompt_tokens_details`/`completion_tokens_details`/`input_tokens_details`/`output_tokens_details`/`credit`，**故意不含歧义的顶层 `cached_tokens`**）、`NormalizedUsageFields`（camelCase，含 `inputTokensDetails`/`outputTokensDetails`）、`RawLine`（`type`/`role`/`sessionId`/`timestamp`/`providerData`） |
| `parse_shell` | 必须是 JSON **对象**（`[]` 会被 serde 读成空 struct，故显式拒绝非 `{` 开头）；`message`+`assistant` 与 `function_call`（role 缺失或 `assistant`）为 `Shell::Usage`，其余为 `Shell::NotUsage`；解析失败为 `ShellError::JsonSyntax`（固定码 `json_syntax_error`） |
| `UsageShell` | 白名单字段 + `timestamp: Option<i64>` + `timestamp_malformed` + `has_any_usage_object()` |
| `parser_contract_check` | 启动自检：assistant message / 无 role function_call 必须被接受，user / reasoning / function_call_result / role 缺失的 message 必须被排除，非对象与坏 JSON 必须报固定码，credit 字面量必须保真 |

正文（`content`、`toolArguments`、`toolCalls`、顶层 `id` 等）由 serde 直接跳过，**从不进入任何结构**；模块内不出现 `serde_json::Value`。

## 错误场景证据（真实失败）

`gate.txt` 之前有两轮真实失败：

1. clippy 报 3 条 `dead_code`（`NumberText::as_str`、`ShellError::as_str`、`UsageShell::has_any_usage_object` 只在测试中使用）→ 按既定规则**不加抑制**，改为在启动自检中真实调用（credit 字面量保真、固定码、usage 存在性），同时补一条"非对象必须拒绝"的自检。
2. 两个测试失败暴露了真实缺陷与夹具错误：`parse_shell(b"[]")` 返回 `Ok(NotUsage)` —— serde 允许把**序列**读进 struct（字段按序），所以数组会静默变成空壳；已在 `parse_shell` 中显式要求 `{` 开头。另一处是自检的 excluded 列表里混进了一条**本应接受**的 `message`+`assistant` 行，删除该条（未放宽任何真实规则）。

## 结论

PASS（AC017 满足：`message`+`assistant` 与无 role 的 `function_call` 纳入候选，`user`/`reasoning`/`function_call_result` 及其他类型全部排除；正文与工具参数不进入任何结构；非整数不被强转）。本项只实现外壳解析，身份与 Token 规则留给 S03.02–S03.06。
