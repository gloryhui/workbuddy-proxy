## 交付内容

| 项 | 内容 |
|---|---|
| `StatsFilter::key()` | **纳入 `source_scope`** —— 范围是查询身份的一部分 |
| `PendingGroupDto` | `model_id`/`count`/`first_at_ms`/`last_at_ms`/`reason`（**无正文、无路径**） |
| `PendingCursor` | `mapping_revision` + `after_model` + `limit`；`validate()` 对"页大小非法"返回 `invalid_argument`、对"修订已变"返回 `cursor_expired`（两种含义不同，不混用） |
| `pending_page(conn, cursor, limit, mapping_revision)` | 按模型排序、**严格从上一页最后一个模型之后**继续，返回本页与下一页游标 |

## 修正的真实缺陷

`StatsFilter::key()` 之前**没有**包含 S08.01 新增的 `source_scope`。后果是：用户把来源从"全部"切到"仅内置"后，旧分页游标**仍然有效** —— 客户端会拿着"全部"的游标去读"仅内置"的第二页，得到一个既不是前者也不是后者的结果集。这正是 AC061 第一条要防的事。修正为把 `source_scope` 纳入 key 之后，`validate_cursor` 的既有 `filter_key` 比对会自动拒绝旧游标（返回 `cursor_expired`），无需额外分支。

## AC061 覆盖

| 要求 | 用例与断言 |
|---|---|
| 切来源旧 cursor 拒绝 | `switching_the_source_scope_invalidates_a_cursor`（三个 scope 的 `filter_key` **两两不同**；同 scope 稳定；用 `supplier` 的游标去查 `builtin` → 错误含 `ERR_CURSOR_EXPIRED`） |
| 归属撤回旧 cursor 失效 | `a_mapping_change_invalidates_a_pending_cursor`（修订 3 → 4 时 `validate(4)` 返回 `cursor_expired`；而页大小非法返回 `invalid_argument` —— 两种失败可区分） |
| 并发追加不重复分页 | `a_candidate_arriving_mid_paging_never_shifts_an_existing_page`（先读 `[m1,m2,m3]`；分页期间到达 `m0` 后重读为 `[m0,m1,m2,m3]` 而**已显示的组一个也没移位**；从 `after_model="m3"` 续页时 `m0` **不会**被重复展示） |
| 页大小受限 | `an_impossible_page_size_is_refused`（`limit=7` → `invalid_argument`） |

## 错误场景证据（真实失败）

实现阶段有三轮真实失败：

1. `E0425`/`E0422`：`query.rs` 未导入 `PendingCursor`/`PendingGroupDto`（批量 import 替换因格式已变而未生效）→ 改为在 import 块首行精确插入。
2. `E0599`：`RequestCursor` **没有** `Default`，测试里的 `..Default::default()` 无法编译 → 按真实字段完整构造夹具。
3. clippy `map_identity`：`.map_err(|code| code)` 是恒等映射 → 直接 `?`；第一次按文本替换未命中（rustfmt 已换行），改为**按行号删除 + 行尾追加 `?`** 后解决。
