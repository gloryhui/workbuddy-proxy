## SQL 人工检查（日志 `sql-inspection.txt`）

| 检查 | 结果 |
|---|---|
| 破坏性语句 | 仅 `DROP VIEW stats_request_facts`（视图重建）与 `DROP TABLE usage_requests`（有意的表重建，重建后立即 `RENAME`）；**无** `DELETE FROM`、`TRUNCATE`、`VACUUM`、`writable_schema`、`DROP INDEX`、`DROP TRIGGER` |
| 备份时机 | `migrate` 仅在 `version > 0` 时走 SQLite Backup API，全新库不备份 |
| 失败传播 | 每个 `apply_step` 都以 `?` 传播；v2/v7 的 FK-OFF 路径用 `let upgraded = …; FK ON; upgraded?;` 保证先恢复外键再传播错误 |
| 隐藏回退 | 未发现 `let _ = apply_step(…)`、`unwrap_or(())`、`.ok();` 之类吞错写法 |
