## 交付内容

| 项 | 内容 |
|---|---|
| `ConfigObservation` | 只有四个字段：`managed`（是否我方）、`model_id`、`route_id`、`observed_at_ms`。**没有凭据字段，也没有 URL 字段**——它们从不被复制出来，连"留待以后比较"都不留。 |
| `observe_current(value, local_key, now_ms)` | 先判签名（委托 S05.01 的共享判定），仅在是我方条目时才读模型 ID 与 route；直连条目一律 `managed=false`、`model_id=None`、`route_id=None`。 |
| `interval()` | 恒为 `(observed_at_ms, None)`：区间**从观测时刻开始**，永不倒推。 |
| `is_usable()` | `managed && model_id.is_some()`；直连配置或缺少模型声明都不可用于分类。 |
| `covers(at_ms)` | 仅在可用且 `at_ms >= observed_at_ms` 时为真——比观测时刻更早的记录**不被覆盖**。 |
| `current_model_id` | 只读模型声明：`model` 字符串，或 `models` 数组（字符串元素或对象的 `id`），空串不算。 |

**不倒推的实现要点**：观测结果里根本没有"过去的区间"这种概念——`interval()` 的起点就是观测时刻本身，`covers()` 对更早的瞬时返回 `false`。因此今天的直连配置无法把历史记录说成直连，今天的代理配置也无法把历史记录说成代理；这类旧区间留给 S05.03 的 `pending` 分支处理。
