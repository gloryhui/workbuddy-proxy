## 交付内容

| 项 | 内容 |
|---|---|
| `READ_CHUNK` | `64 KiB`，每次 `read` 的上限 |
| `MAX_LINE_BYTES` | `4 MiB`，**含端点**（恰好 4 MiB 接受，超 1 字节即 oversized） |
| `BOM` | UTF-8 BOM，**仅**在文件偏移 0 处剥离；后续行中出现的同样字节是内容 |
| `Line` | `start`/`end`（`end` 覆盖终止符）/`bytes`（去掉终止符、行尾 `\r`、起始 BOM）/`oversized` |
| `LineReader` | `open(path, offset)` + `next_line()`；`buffered_bytes()` 暴露当前行占用的上界 |
| 有界性 | 超限行**立即丢弃已缓冲内容**（`pending = Vec::new()`）并继续排空到下一个 `\n`，因此内存上界为 `MAX_LINE_BYTES + READ_CHUNK`，与磁盘上的行有多长无关 |
| 未终止尾行 | **不是一行**：EOF 时若有残留片段则直接丢弃并返回 `None`，`end` 永不越过最后一个 `\n` |

**不 `read_to_end`**：全程只有 `[u8; 64 KiB]` 的固定块与当前行的缓冲；测试用 5000 行文件与 50 MiB 单行分别断言峰值。

## AC027 覆盖

| 要求 | 用例与断言 |
|---|---|
| 4 MiB 边界 | `the_four_mebibyte_boundary_is_inclusive`（恰好 4 MiB → 接受且 `bytes.len() == MAX_LINE_BYTES`；4 MiB + 1 → `oversized`、`bytes` 为空、`end` 仍前进到终止符之后） |
| 50 MiB 单行内存有界 | `a_fifty_mebibyte_line_stays_bounded_in_memory`（50 MiB 单行 → `oversized`，`end == 50 MiB + 1`，`buffered_bytes() <= 4 MiB + 64 KiB`，随后 `after` 正常读出） |
| 不加载整文件 | `a_long_file_is_read_line_by_line_without_loading_it`（5000 行逐行读出，峰值 ≤ `MAX_LINE_BYTES + READ_CHUNK`） |
| 完整行可被后续处理 | `lf_lines_are_read_one_by_one`、`line_offsets_cover_the_terminator`（`(0,2)`、`(2,5)`、`(5,6)`，空行保持为空） |
| CRLF | `crlf_terminators_are_trimmed`（`\r\n` 去掉 `\r`；行内裸 `\r` 保留为数据） |
| BOM | `a_utf8_bom_is_skipped_only_at_the_very_start`（偏移 0 剥离；后续行中的同样字节保留） |
| 无尾换行 | `an_unterminated_tail_is_never_returned`（**X11/DATA-API §5**：`one\ntwo\npartial` 只返回 2 行且 `end == 8`，即偏移停在最后一个 `\n`；追加 `\n` 后同一批字节成为第 3 行且 `end == 32`） |
| 超长行排空后可继续 | `an_oversized_line_is_drained_and_the_next_line_is_readable`（oversized 行之后的 `good` 正常读出） |
| 从偏移开始 | `reading_starts_at_the_given_offset`（`offset=4` → `two`，`(start,end) == (4,8)`） |

## 错误场景证据（真实失败）

`gate.txt` 之前有一轮真实失败：

1. `an_unterminated_tail_is_never_returned` 中追加换行后的期望偏移写成 **33**，实际为 **32**（`one\n` 4 + `two\n` 4 + 23 字节片段 + `\n` 1）。测试夹具未改，只修正了手算的期望值。
2. clippy `buffered_bytes` 从未使用 → 按既定规则**不加抑制**，改为在启动自检中于 `/dev/null` 上真实调用并断言上界。
