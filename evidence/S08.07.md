## AC063 第二条：不靠吞反序列化错误显示空页

`gpui/src/stats_backend.rs` 的解析逻辑原本与 HTTP 调用耦合、无法直接测试。本项把它**提取为纯函数**（真实重构，非为测试而测试）：

```rust
pub fn parse_message(success: bool, data: &Value) -> Result<Value, String>
```

三条语义被测试锁定：**格式错误的 payload 是错误**（`Invalid statistics response`）、**失败的 envelope 保留 core 的错误信息**、**合法 payload 正常解析**。因此协议不匹配会**明确报错**，不会被"解析失败 → 空页"掩盖。

## 环境限制（如实记录）

`scripts/core_compatibility.py` 在**本机无 GUI 会话**的环境下无法完成：它启动的是 GPUI 桌面二进制，脚本要求其"干净退出"，而该二进制在此环境下 15 秒内不退出（`subprocess.TimeoutExpired` → `Native controller did not quit cleanly`）。这不是本次改动引起的（脚本在 S08.06 之前的行为相同），而是**运行环境缺少桌面会话**。

等价证据由两条**可执行**的路径提供：

1. `src/frontend.rs` 的 `compatibility_tests`（单元测试，**已通过**）：同一版本 + 协议 10 → **不兼容**、协议 11 → 兼容、旧版本 + 协议 11 → 不兼容。
2. `scripts/core_compatibility.py` 的**逻辑**已更新为"当前 11、旧协议含 10"，待有桌面会话的环境执行（登记为遗留）。

## 错误场景证据（真实失败）

1. `E0425` ×3：测试引用了不存在的函数名 `unwrap_reply` —— 实际解析逻辑内联在 `pub fn call(...)` 中。**没有**把测试改成调用 HTTP，而是**提取** `parse_message` 纯函数（可测性真实提升），再让 `call` 调用它。
2. `core_compatibility.py` 首次运行 `AssertionError: Native controller did not quit cleanly` —— 先误传核心二进制，改传 GPUI 二进制后仍因**无桌面会话**超时；据此判定为环境限制并给出等价证据（见上）。
3. 第一次批量更新协议断言后 `grep` 复查发现**第 7 处**残留（`native_protocol_test.py`），补改 —— 这正是"复查"步骤的价值。
