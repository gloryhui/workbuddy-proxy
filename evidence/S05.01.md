## 交付内容

`workbuddy.rs` 中原先内联在 `managed_signature` 里的判断被拆成四个**非敏感**共享小函数（逻辑逐字搬移，**行为不变**）：

| 函数 | 读什么 | 不读什么 |
|---|---|---|
| `has_managed_marker` | `_workbuddyProxy/managed` 布尔标记 | 其它一切 |
| `is_custom_vendor` | `vendor` 字面量 | 名称、别名 |
| `looks_like_local_key` | 凭据的**形状**（等于本机 key 或 48 位十六进制） | 不返回、不记录、不存储凭据 |
| `is_loopback_endpoint` | scheme/host/path 形状（仅 `127.0.0.1`/`localhost`/`[::1]`，path 为 `/v1` 或 `/r/<id>/v1`） | 不解析任何显示名 |

`managed_signature` 现在只是这四个的组合，语义与原实现逐分支等价；`route` 改为 `pub`（classify 需要 route id）。

`classify.rs` 不新增任何检测规则，只做委托：

```rust
pub fn carries_proxy_signature(value: &Value, local_key: &str) -> bool {
    has_managed_marker(value)
        || (is_custom_vendor(value) && looks_like_local_key(value, local_key) && is_loopback_endpoint(value))
}
pub fn proxy_route(value: &Value, local_key: &str) -> Option<String>
```

`classify_contract_check()` 在启动路径上断言：标记生效、旧形状可识别、route 正确、**按名称/别名/裸 `localhost` 一律不成立**、外来 key 不成立，并检查 `classify.rs` 的生产部分**不含第二套检测器**（无 `reqwest::Url`、无 `host_str`、无 `is_ascii_hexdigit`）。

## 错误场景证据（真实失败）

`gate.txt` 之前有两轮真实失败，都是**检查器自身**的问题（实现逻辑未改）：

1. `classify_contract_check` 的禁止词检查命中 `include_str!` 里的**测试模块**（测试要构造 `http://127.0.0.1:1/v1` 等样本 URL）→ 改为只检查 `#[cfg(test)]` **之前**的生产部分，并把检查目标从"字面量"升级为"第二套检测器的实质标志"（URL 解析、主机判断、key 形状判断），语义更强。
2. 仍失败：`apiKey` 作为禁止词会命中**契约检查自身**构造样本条目的必要字段 → 去掉该 needle，并在代码注释中写明"凭据字段名不是 needle，因为自检必须构造样本"。
