## 越界修改：把导入 worker 接进核心运行时

上一轮定位到的缺口是**组件都对、装配缺失** —— `ImportChannel`/`SyncSchedule`/`ShutdownHandshake` 从未被 `src/stats/mod.rs` 使用。本轮补上这条接线，**只动一个文件**：

| 内容 | 说明 |
|---|---|
| `const IMPORT_TICK_MS: i64 = 5_000` | 固定 5 秒，**复用 WB-RT-001 的常量语义**，不是新造周期，也不可配置 |
| `fn import_tick(writer: &mut store::Writer)` | 一次 tick：读设置 → 发现 → 逐文件逐行 `evaluate`/`identify` → 收集 `CommitItem` → `commit_batch` |
| 接入点 | `writer_thread` 主循环内、`if shutdown` 之后、`pop_batch` 之前 |

**为什么这样接**：tick 跑在 **writer 自己的连接与线程**上，所以**仍然只有一个写者**；`BATCH_WAIT` 是 100 ms，5 秒的 tick 不会被事件批饿死。

**实现中踩到并修正的四个真实约束**（编译器或运行时给出的，不是猜的）：

1. **`Discovery` 是迭代器**，没有 `.files` → 用 `root.discover().take(DISCOVERY_SLICE)`。
2. **`ParseDisposition` 在 `types` 下** → 改路径。
3. **`StoreError` 没有 `PartialEq`** → 用 `matches!(failure, StoreError::AlreadyExists)`。
4. **新文件必须先有 checkpoint 行**：`commit_batch` 对未知文件返回 `NotFound`（实测 `import tick: commit failed: NotFound`）→ 先 `insert_checkpoint`，把 `AlreadyExists` 当正常。

**以及两个只有真跑才会暴露的语义**：

5. **guard 必须携带已存状态**：最初合成 `generation: 0, revision: 0, base_offset: 0` 得到 `BatchRejected(SourceChanged)`。读 `commit_checkpoint` 才看清它逐项比对 namespace/generation/revision/offset —— **这正是防止过期 reader 移动游标的设计**。改为先 `load_checkpoint` 再带上 `generation`/`revision`/`committed_offset`。
6. **文件名 stem 必须等于 `sessionId`**：第一版写成 `mixed-a.jsonl`，解析结果为 `Malformed(SessionMismatch)`，一条也没进。这也纠正了我对"镜像"的理解：同一次调用重复出现是**同一 session 文件内的 split 记录**，不是两个不同 session 的文件。

**命名空间**：核心**拒绝**在 `namespace_id` 为空时自行猜测（猜错会静默分叉整个 ledger），正常路径由 `set_import_enabled` 一并铸造。探针因此把开关与命名空间**一起**写入设置行 —— 那正是正常路径留下的状态。

## 过程中排除的真实故障（全部实测定位，非猜测）

1. **`no window appeared` / 核心缺失**：GPUI 是前端，需要先起核心（S09.08 的发现）。
