## 交付内容

| 项 | 内容 |
|---|---|
| `PREFIX_LEN` / `ANCHOR_LEN` | `4096` / `256` 字节 |
| `FileFingerprint` | `prefix_hash`/`prefix_len`（`min(size, PREFIX_LEN)`，小文件被**完整覆盖**）、`anchor_hash`/`anchor_start`/`anchor_len`（已提交偏移前的 `ANCHOR_LEN` 字节窗口，提交不足时从 0 开始） |
| `StoredFingerprint` | 检查点侧的记忆：`committed_offset`/`observed_size` + 上述五个指纹字段（对应 `workbuddy_import_files` 的既有列） |
| `fingerprint(path, committed_offset)` | 读取并计算待存指纹 |
| `decide(...)` | **纯决策表**：头部或锚点不匹配 → `Replaced`；否则按 `size` 与 `observed_size` 比较 → `Appended` / `Truncated` / `Unchanged` |
| `classify_change(path, stored)` | 读盘判定：symlink/目录 → `Replaced`（不读内容）；`size < committed_offset` → `Truncated`；比记忆区间更短 → `Truncated`；否则用 `decide` |
| `FileChange` | `Unchanged` / `Appended` / `Truncated` / `Replaced` |

**小文件不误判的关键**：比较时**按记忆的 `prefix_len` 重新散列当前文件的前 `prefix_len` 字节**，而不是按当前文件长度散列。因此 `"line-one\n"`（9 B）增长为 18 B 时，前 9 字节的散列不变 → `Appended`，不会被误判为 `Replaced`。

**锚点的作用**：文件长度只增不减、头部完好，但**已提交区间内的字节被改写**时，只有锚点散列能发现 → `Replaced`（例如同长度改写、或改写后再追加）。

`Replaced`/`Truncated` 只**报告**事实；generation 递增由调用方在 S04.05 的事务内执行，账本条目按 S02.04 的终态语义**永不删除**（tombstone 不可复活）。

## AC026 覆盖

| 要求 | 用例与断言 |
|---|---|
| 小文件增长不误判 | `a_small_file_that_grew_is_an_append_not_a_replacement`（`prefix_len == 9` 覆盖整个小文件；增长后仍 `Appended`）、`repeated_growth_of_a_small_file_stays_an_append`（连续 4 次增长，每次都重新检查点） |
