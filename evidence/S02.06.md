## 交付内容

### 历史归属映射（`workbuddy_model_history`）

| 项 | 内容 |
|---|---|
| 枚举 | `MappingClass`（proxy/direct）、`MappingEvidence`（observed_config/managed_sync/manual）、`MappingState`（prepared/verified/conflict/revoked）、`ReconcileState`（pending/running/completed），全部闭集 + `ALL`/`as_str`/`parse` |
| `ModelMapping` / `NewMapping` | 对齐全部 17 列；`valid_to_ms: Option<i64>` 表示半开区间上界（`None` = 无上界） |
| `insert_mapping` | 先查重键；`valid_to_ms <= valid_from_ms` 拒绝；`verified` 写入前用 `overlapping_verified` 做 Rust 侧重叠检查（SQL 触发器仍作兜底） |
| `overlapping_verified` | 与触发器同式的重叠计数（半开区间、`COALESCE` 无上界、可排除自身） |
| `set_mapping_state` | 转为 `verified` 时**再次**检查重叠；行不存在返回 `NotFound` |
| `match_mapping` | 半开区间 `valid_from <= at < valid_to`、仅 `verified`；`LIMIT 2` → `None` / `One` / **`Conflict`**（绝不挑最新） |

| 项 | 内容 |
|---|---|
| `ImportSettings` | `enabled` / `namespace_id` / `mapping_revision` / `last_full_scan_ms` / `revision`（沿用既有单例 `revision` 做 CAS） |
| `set_import_enabled` | CAS 更新；启用且 namespace 为空时用 `config::token()`（24 字节 → **48 hex**，正好匹配 schema 的 `length IN (0,48,64)`）生成一次；**关闭保留 namespace**，再次启用复用同一 ID |
| `SettingsOutcome` | `Updated` / `Conflict { current_revision }`；`UPDATE` 影响行数 ≠ 1 时也按冲突处理 |
| `mapping_contract_check` | 内存库启动自检：启用→关闭→再启用（namespace 必须不变）、相邻区间插入、重叠拒绝、`match_mapping` 命中、`set_mapping_state` 撤销与重新验证、过期 settings revision 必须返回冲突 |

## AC014 覆盖

| 要求 | 用例 |
|---|---|
| 相邻区间合法 | `adjacent_half_open_intervals_are_legal`（`[100,200)`+`[200,300)`+`[300,∞)`；199→m1、200→m2、300→m3、99→None、未知模型→None） |
| 重叠拒绝 | `overlapping_verified_intervals_are_refused_by_rust_and_by_the_trigger`（Rust 侧 `Overlapping`；绕过 Rust 的裸 SQL 被触发器以 `overlapping model mapping` 拒绝；`prepared` 可重叠） |
| 关闭再开 namespace 不变 | `the_namespace_is_created_once_and_reused_after_toggling`（启用生成 48 hex；关闭保留；再启用相同；新连接读取仍相同） |
| 多匹配不猜测 | `two_verified_matches_report_a_conflict_instead_of_picking_one`（显式删触发器构造损坏态后，`175ms` → `Conflict`，`120ms` → `One`） |
| 设置 CAS | `a_stale_settings_revision_is_refused`（过期 revision → `Conflict{current+1}`，且启用状态未被改写） |
| 区间非法 | `an_invalid_interval_is_refused`（`to == from` 与 `to < from` 均 `InvalidOffset`） |
| 状态转换复核 | `verifying_a_prepared_row_checks_the_interval_again`（`prepared`→`verified` 重叠被拒；未知 id → `NotFound`） |
| 码闭集 | `mapping_states_and_codes_are_closed`（`duplicate` 不是状态、`guessed` 不是证据；可用状态恰 1 个） |

## 错误场景证据（真实失败）

`gate.txt` 之前共 3 轮真实失败，均保留在会话日志链中：

1. `Display` 未覆盖新增变体（`E0004`）与 `conn.execute` 收到 `String` 而非 `&str`（`E0308`）→ 补齐分支、改用 `format!` + `&raw`。
2. clippy：`SettingsConflict` 变体从未构造、`set_mapping_state` 从未使用、`redundant closure`、`collapsible_if` → 前两者通过在启动自检中真实调用/匹配解决，后两者按建议改写；`StoreError::SettingsConflict` 因语义上由 `SettingsOutcome` 承担而**删除**（不是抑制）。
3. `two_verified_matches_report_a_conflict_instead_of_picking_one` 失败：`UPDATE ... SET state='verified'` 被重叠触发器拒绝 —— 这本身证明触发器有效；测试改为显式 `DROP TRIGGER` 构造损坏态，再断言匹配器仍报 `Conflict`。
