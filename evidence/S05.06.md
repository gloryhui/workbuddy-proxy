## 交付内容

| 项 | 内容 |
|---|---|
| `load_mappings_in_state(tx, state)` | 按状态列出映射行（按 `mapping_id` 排序，结果确定） |
| `PreparedRecovery` | `completed` / `conflicted` 计数与 `total()` |
| `recover_prepared(tx, enabled, present, now_ms)` | 启动恢复：对每条 `prepared` 行调用 `present(mapping)` 对照**实际存在的非敏感配置** |

判定规则：

- `present == true`（配置里确实有它）→ **完成**：`verified`；
- `present == false`（写前崩溃，配置里没有）→ **冲突化**：`conflict`；
- 完成时若会与已有 `verified` 区间重叠 → **不覆盖**，同样转为 `conflict`；
- `enabled == false`（导入关闭）→ **整趟跳过**，`prepared` 行原样保留（依然不可用于分类），WorkBuddy 同步不受影响；
- 只处理 `prepared` 行：`verified` / `conflict` / `revoked` 一律不动，重复启动是幂等的。

**为什么三个崩溃点都安全**：`prepared` 行是在写 WorkBuddy 文件**之前**建立的，而 `MappingState::is_usable()` 只认 `verified`。因此无论崩溃发生在写前、写后还是 ACK 前，未决行在分类时都**不参与**（`match_mapping` 只查 `state='verified'`）；启动恢复只是把未决行收敛到确定状态，而不是让它"变成"直连。

| 崩溃点 | 用例与断言 |
|---|---|
| **写前** | `a_crash_before_the_write_conflicts_the_prepared_row`（`present=false` → `conflict`；`is_usable()=false`；`match_mapping` 对该模型返回 `None`，**不会被当作 direct 计入**） |
| **写后** | `a_crash_after_the_write_completes_the_prepared_row`（`present=true` → `verified`；`is_usable()=true`；`match_mapping` 返回 `One`） |
| **ACK 前** | `a_crash_before_the_ack_is_resolved_the_same_way`（同一未决行再次启动 → `total()==0`，**幂等**，不会重复解析，也不会把已确定状态改回去） |
| 导入关闭 | `a_disabled_import_leaves_prepared_rows_untouched`（`total()==0`；行仍为 `prepared`；`is_usable()` 仍为假——同步可用性不受影响） |
| 不覆盖已确认区间 | `recovery_never_overrides_an_already_verified_interval`（重叠时已确认行保持 `verified`，未决行转 `conflict`） |
| 只动未决行 | `recovery_leaves_settled_states_alone`（`verified`/`conflict`/`revoked` 三种已定状态均不被触碰） |
