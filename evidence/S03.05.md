## 交付内容

| 项 | 内容 |
|---|---|
| `CREDIT_NANOS_PER_UNIT` | `1_000_000_000`（1 credit = 10^9 nanos，与 `workbuddy_credit_nanos` 列一致） |
| `MAX_CREDIT_FRACTION_DIGITS` | `9` |
| `parse_credit_nanos(literal) -> Result<i64, CreditRejection>` | **纯文本 + `checked` 整数运算，全程无 `f64`**：拒绝空串、科学计数法（`e`/`E`）、负号、多余小数点、前导/尾随小数点、非数字字符、超过 9 位小数、以及任何溢出 `i64` nanos 的值 |
| `CreditRejection` | `NotDecimal` / `ScientificNotation` / `Negative` / `TooManyFractionDigits` / `TooLarge` |
| `normalize_credit(usage, raw)` | 成功写入 `workbuddy_credit_nanos`；失败**只**置 `diagnostics.credit_invalid`，`workbuddy_credit_nanos` 保持 `None`，**status/reason/Token 值完全不变** |
| `credit_literal(line)` | 启动自检与测试共用的夹具入口，经**真实 `parse_shell`** 取字面量，避免夹具与解析器脱节 |

精确性依据：`NumberText` 保留 JSON 数字的原始文本（`1.140` 就是 `1.140`，`1e3` 就是 `1e3`），credit 规则因此看到的是字面量而非浮点近似值。

| 要求 | 用例与断言 |

## 错误场景证据（真实失败）

`gate.txt` 之前有一轮真实失败：启动自检最初写成 `NumberText::for_test("1.14")`，而 `NumberText` 没有测试构造器，且 `parser.rs` 不在本项允许修改列表内。按最小越界原则改用**公开解析路径**：新增 `credit_literal()`，通过真实 `parse_shell` 从 `providerData.rawUsage.credit` 取得字面量，夹具与生产解析不再可能脱节。
