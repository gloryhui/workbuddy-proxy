## 交付物与设计依据

按 COMMANDS.md「新 Python 集成脚本自行创建 TemporaryDirectory，把 HOME、USERPROFILE、APPDATA（Windows）及 --config-dir 都指向临时路径」「CLI 固定 --exe、--output」「脚本必须先检查源目录是测试 sandbox，且在输出中给出不含用户私有路径的隔离证据」实现 `scripts/workbuddy_import_test.py`。

S01.03 只交付沙箱与“真实 core 落在临时根目录”的证明；解析/读取/导入/生命周期/UI 检查留给后续子任务在同一 harness 上追加。

隔离机制：

| 项 | 实现 |
|---|---|
| 隔离根 | 单个 `tempfile.TemporaryDirectory(prefix='workbuddy-import-')`，`.resolve()` 后使用 |
| 配置目录 | `--config-dir <sandbox>/config`，并额外设 `WORKBUDDY_PROXY_CONFIG_DIR` 双保险 |
| 用户目录 | `HOME`、`USERPROFILE` → `<sandbox>/home`；`APPDATA`/`LOCALAPPDATA`/`XDG_*` → 各自 sandbox 子目录（`src/config.rs:237` 的 `directory()` 与 `:232` 的 `home()` 都会命中沙箱） |
| 临时目录 | `TMPDIR`/`TEMP`/`TMP` → `<sandbox>/tmp` |
| 导入源根 | `<sandbox>/home/.workbuddy`，并断言它不是真实 `~/.workbuddy` |
| 公网价格 | `WORKBUDDY_PROXY_CATALOG_TEST_URL=http://127.0.0.1:1/catalog`（无监听端口，`src/price_catalog.rs:186`、`src/catalog.rs:784` 的运行时读取点） |
| 子进程 | `subprocess.Popen(env=<完整沙箱环境>, cwd=<sandbox>)`，`start_new_session=True`，`atexit` + `finally` 回收；不使用会丢环境的启动路径 |
| 真实路径保护 | 只对真实 `~/.workbuddy`、`~/Library/Application Support/WorkBuddyProxy`、`~/.config/workbuddy-proxy` 做 `stat` 元数据快照对比（**不读内容、不写文件**），运行前后必须一致 |

## 错误场景证据（`dist/workbuddy-import-validation/S01.03/negative-and-privacy.txt`）

1. **缺失 core 二进制**：`--exe target/release/definitely-not-built` → `FAIL: 19 passed, 1 failed`，`negative1_exit=1`，报告 `error=core_binary_missing`。证明脚本不会把“没跑真实二进制”写成通过。
2. **泄漏的 HOME 会被检出**：把 `environment()['HOME']` 改回真实 home 后，`leaked HOME flagged as outside sandbox -> True`，且真实 `~/.workbuddy` 与沙箱源根不同 → `True`。证明隔离断言不是恒真检查。
3. **隐私扫描**：对生成的 JSON 报告 `grep -c '/Users/'` = `0`，`grep -c 'glory'` = `0`；报告只记录 `sandbox_location=tmp:/workbuddy-import-…`（相对系统临时根）与布尔事实，不含用户私有绝对路径。
4. 首轮真实运行中曾出现 `report.passed_doc()` 笔误，运行前已修正为 `Report.passed` / `Report.failed_count`，故 `run.txt` 不是笔误版本的产物。
