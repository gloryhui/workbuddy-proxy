## 交付内容

| 项 | 内容 |
|---|---|
| `CommitItem` | 一条待提交候选：`entry_key`/`session_hash`/`message_hash`/`requested_model`/`event_at_ms`/`normalized_hash`/`attribution`/`candidate_json`/`origin` |
| `CommitReport` | `imported`/`excluded_proxy`/`pending`/`duplicates`/**`committed_offset`** |
| `commit_batch(tx, namespace, guard, update, expected_settings_revision, items, now_ms)` | 在**调用方的事务内**完成：复核 settings revision → 逐项写 ledger（+ 事实行）→ 提交 checkpoint |

关键语义：

1. **任一 SQL 失败全批 rollback**：所有写入都在同一个 `Transaction` 内，函数本身**不 commit**；任何 `Err` 都让调用方 `rollback`，ledger、事实行与 checkpoint 一起消失。测试用一个 `entry_key` 长度非法的项触发 `CHECK` 失败，回滚后 `(ledger, facts, offset)` 仍为 `(0, 0, 0)`。
2. **offset 不得领先事实**：checkpoint 只在**每一项都写成功之后**才提交，且与事实行同事务。成功路径断言"`state='imported'` 的 ledger 行中，没有一条缺少对应事实行"（`imported_without_fact == 0`）。
3. **当前 revision 再校验**：`expected_settings_revision` 与库中实际 revision 不符时，函数在**任何写入之前**返回 `SettingsStale`（测试断言 ledger 仍为 0 行）。命名空间不符同样拒绝。
4. **同键不写第二条事实**：已存在同 `entry_key` 的行计为 `duplicates` 并跳过 —— 不会产生第二行事实。
5. **代理/待定行不写事实**：只有 `imported` 分支插入 `usage_requests`；`Proxy` 与 `Pending` 分别写 `excluded_proxy` 与 `pending_classification`（后者保留白名单 `candidate_json`）。
6. **导入事实行的形状**：`source='workbuddy_import'`、`outcome='recorded'`、`usage_source='workbuddy_jsonl'`、`time_basis='message_timestamp'`，并且**显式传 `upstream_protocol = NULL`**（该列有 `DEFAULT 'openai_chat'`，S02.02 已记录的偏差）。

## AC042 覆盖

| 要求 | 用例与断言 |
|---|---|
| 任一 SQL 失败全批 rollback | `a_failed_item_rolls_the_whole_batch_back`（第二项 `entry_key` 非法 → 批次报错；`rollback` 后 `(ledger, facts, offset) == (0, 0, 0)`） |
| offset 不得领先事实 | `the_offset_never_leads_the_facts`（三项混合批次：`(imported, proxy, pending, offset) == (1, 1, 1, 64)`；`imported_without_fact == 0`；事实行恰 1 条；提交后落库计数 `(3, 1, 64)`） |
| 当前 revision 再校验 | `a_stale_settings_revision_is_refused_before_any_write`（`revision + 1` → `SettingsStale`，且 ledger 仍 0 行） |
| 同键重放 | `a_duplicate_key_is_a_no_op_and_the_offset_still_advances_once`（同键第二批计为 `duplicates` 且不写第二条事实；因 checkpoint 已移动，该批整体被 `BatchRejected` 拒绝） |
| checkpoint 拒绝可辨 | 同上（`StoreError::BatchRejected(BatchRejectReason)` 携带固定拒绝原因，而非泛化错误） |

## 错误场景证据（真实失败）

`gate.txt` 之前有四轮失败，其中**前两轮是接口/夹具约束**、后两轮是**检查器自身**：

1. `E0599`/`E0609`：`CheckpointGuard::revision` 是**字段**而非方法，`CheckpointAck::Committed` 携带 `CommitOutcome`（含 `committed_offset`）而非直接字段；`StoreError` 也没有现成的 `StaleBatch` 变体 → 新增 `BatchRejected(BatchRejectReason)` 并按真实 API 改写。
2. `E0560`：`CheckpointUpdate` 没有 `prefix_len`/`anchor_start`/`anchor_len` 字段（它们由 guard 推导），`prefix_hash`/`anchor_hash` 是 `Option<String>` → 按真实定义构造。
3. `CHECK constraint failed: length(file_key)=64`：`workbuddy_import_files.file_key` 要求恰 64 字符，而夹具用了 `"batch"` → 引入 `batch_key()` 统一补齐（测试与自检共用同一规则）。
4. `QueryReturnedNoRows`：回滚后 checkpoint 行不存在，`counts()` 的 `query_row` panic → 改为 `COALESCE(MAX(committed_offset), 0)`，使"没有行"本身就是可断言的 0。

## 结论

PASS（AC042 满足：批次内任一 SQL 失败时 ledger、事实行与 checkpoint 一并回滚；committed offset 只在全部事实行写成功后于同一事务内推进，且经断言不存在"已导入但没有事实"的行；settings revision 在写入前复核）。本项只实现提交事务，不解析文件、不调度、不启动线程。
