## 交付内容

| 项 | 内容 |
|---|---|
| `Checkpoint` | 对齐 `workbuddy_import_files` 的全部 20 列（generation/revision/committed_offset/observed_size/modified_ms/prefix_hash/prefix_len/anchor_hash/anchor_start/anchor_len/discarding_oversized/scan_offset/scan_generation/last_seen_at_ms/last_completed_at_ms/last_error_code/diagnostic_counts_json） |
| `NewCheckpoint` / `insert_checkpoint` | 新发现文件以 `generation=1, revision=1, committed_offset=0` 登记；已存在返回 `AlreadyExists` |
| `CheckpointGuard` / `CheckpointUpdate` / `commit_checkpoint` | 乐观 CAS：批次必须匹配 **namespace + generation + revision + base_offset** |
| `diagnostics_json` | 把闭集诊断键序列化为固定形状 JSON（恒为 10 个固定键，键序即 `DiagnosticKind::ALL`） |
| `checkpoint_contract_check` | 内存库启动自检：插入 → 提交 → 同 guard 再提交必须 `stale_batch` → revision 复核 → rollback |

拒绝语义（全部**不写任何行**）：

| 条件 | 结果 |
|---|---|
| namespace 不匹配（跨 namespace） | `CheckpointAck::Rejected(stale_batch)` |
| generation 落后（文件被替换） | `CheckpointAck::Rejected(source_changed)` |
| revision 或 base_offset 不匹配 | `CheckpointAck::Rejected(stale_batch)` |
| `next_offset` 为负、`base_offset` 为负、或 `next_offset < base_offset` | `Err(StoreError::InvalidOffset)` |
| 行不存在 | `Err(StoreError::NotFound)` |
| `next_offset == base_offset`（文件未增长） | **允许**：仍提交并 `revision + 1`，供后续批次观察 |
| 读取与写入之间行被改动（`UPDATE` 影响行数 ≠ 1） | `CheckpointAck::Rejected(stale_batch)` |

`StoreError` 由 S02.04 的 `LedgerError` 重命名而来（账本与检查点共用），新增 `InvalidOffset` 变体；S02.04 证据中的旧名称对应此类型。

## AC013 覆盖

| 要求 | 用例 |
|---|---|
| 错误 revision 拒绝且无部分写 | `stale_revision_is_refused_without_a_partial_write`（过期 guard → `stale_batch`；`(revision, committed_offset)` 仍为 `(2, 64)`；错误 base_offset 同样被拒） |
| 旧 generation 拒绝 | `an_old_generation_is_refused`（文件被替换后 generation=2，旧 guard → `source_changed`，generation 保持 2） |
| 负 offset 拒绝 | `negative_or_regressing_offsets_are_refused`（`next<base`、`next<0`、`base<0` 三例均 `InvalidOffset`，且 rollback 后 `committed_offset` 仍为 64） |
| 跨 namespace 拒绝 | `a_foreign_namespace_is_refused`（`revision` 仍 1、`committed_offset` 仍 0） |
| 未变文件支持 | `an_unchanged_file_can_commit_at_the_same_offset`（同 offset 提交成功且 revision 前进） |
| 首次登记与重复登记 | `a_missing_checkpoint_is_reported`（缺失 → `NotFound`；重复 `insert_checkpoint` → `AlreadyExists`） |
| 诊断 JSON 闭集 | `diagnostics_json_keeps_the_closed_key_set`（硬编码 10 键期望，`matches(':').count() == 10`，落库值一致） |
| 正常提交 | `first_commit_advances_revision_and_offset`（revision 1→2、offset 0→64、observed_size/prefix_hash/last_completed_at_ms 更新） |

## 错误场景证据（真实失败）

`gate.txt` 之前有一轮真实失败：`first_commit_advances_revision_and_offset` 与 `diagnostics_json_keeps_the_closed_key_set` 的期望写成了“只输出非零键”，而实现输出**全部 10 个固定键**。按 DATA-API §3.2「固定错误码→非负计数」的“固定形状”语义，保留实现并把期望改为**硬编码的完整闭集字符串**（不使用实现生成期望），并补一条键数断言。
