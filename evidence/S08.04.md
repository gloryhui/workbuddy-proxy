## 交付内容

八个命令共用一个入口，这让两条承诺集中在一处可被检查：

```rust
pub fn handle_command(conn, command, payload, now_ms) -> Result<String, String>
```

| 命令 | 行为 |
|---|---|
| `stats_workbuddy_status` | 从持久层读设置与计数 → `state`/`enabled`/`effective_enabled`/`root_found`/`settings_revision`/`files_*`/`imported`/`excluded_proxy`/`pending`/`conflict`/`deleted`/`bytes_processed`/`last_error_code`/**`complete`** |
| `stats_workbuddy_settings_update` | `enabled` + `expected_revision` 的 CAS；开启时建立命名空间；旧 revision 返回 `stats_revision_conflict` |
| `stats_workbuddy_scan` | 只**入队**（返回 `scan_id` 与 `state="queued"`），**请求内不读任何文件**；导入关闭时返回 `stats_workbuddy_import_disabled` |
| `stats_workbuddy_pending` | 按模型分组返回 `model_id`/`count`/`first_at_ms`/`last_at_ms`/`reason`；`limit` 只接受 20/50/100；**不含正文与绝对路径** |
| `stats_workbuddy_mapping_preview` | `preview_mapping` → `affected_count`/`watermark_rowid`/`mapping_revision`/`token`/`expires_at_ms` |
| `stats_workbuddy_mapping_apply` | 复核 token → `claim_mapping_task` → 用**当前**保留窗口 `confirm_pending_rows` |
| `stats_workbuddy_mapping_revoke_preview` | 复核 `expected_revision` → 返回受影响已导入条数与到期时间 |
| `stats_workbuddy_mapping_revoke` | 分批 `revoke_mapping_rows`（每批 ≤256），返回 `withdrawn`/`finished` |

**两条 AC060 承诺**：

1. **错误码固定、无 SQL 路径**：`store_code()` 把每一个 `StoreError` 映射到 11 个常量之一；未知命令返回 `stats_workbuddy_invalid_path`，**不回显请求内容**。`WORKBUDDY_ERROR_CODES` 由启动自检断言"数量为 11、全部以 `stats_workbuddy_` 开头、不含 `/`、空格或引号" —— 常量在结构上无法携带路径或查询。
2. **扫描异步入队**：`scan` 只做一次设置读取与合法性检查，然后返回排队信息；文件读取永远发生在工作线程（S06 已证明导入路径零 tokio/零 async）。

**管理鉴权与 1 MiB 限制**沿用既有控制通道（所有 `stats_*` 命令都走同一条鉴权路径与同一个响应上限），本项没有绕过它们。

## 错误场景证据（真实失败）

实现阶段有五轮真实失败：

1. `E0308` ×10：`store_code` 的 `match error` 匹配到了 **`dto::error` 函数**而不是参数 —— `use crate::stats::dto::*` 把同名函数带进了作用域。参数重命名为 `failure` 后解决。
2. `E0599`：`SettingsOutcome::Unchanged` 不存在（实际只有 `Updated`/`Conflict`）→ 去掉该分支。
3. `E0609`：`ImportSettings` 没有 `retention_days`（保留期属于统计设置）→ 改为在确认前用 `store::load_settings` **重新读取当前窗口**，语义反而更正确。
4. `E0308`：`revoke_mapping_rows` 的批量参数是 `usize` 而 payload 给的是 `i64` → 显式转换并 clamp 到 1..=256。
5. 一次按行改写因旧文本已变而未写入 → 改为**按行号删除 + 逐行断言**。

**一个真实的语义缺陷**（由测试发现）：`ImportStatusDto::is_complete()` 在导入**关闭**时也返回 `true` —— 那等于说"从没看过任何东西 = 全部同步完成"。修正为要求 `effective_enabled`，并把 `complete` 一并发布给客户端。

## 结论
