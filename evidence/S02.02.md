## `store.rs` 的改动

1. `SCHEMA_VERSION: i64 = 7`；新增 `const MIGRATION_0007: &str = include_str!("migrations/0007.sql");`。
2. `migrate` 尾部原来的**无条件** `apply_step(conn, 6, MIGRATION_0006)` 改为 `if version < 6 { ... }`，避免 v6 库重复执行 0006 重建已存在的 catalog 表。
3. 追加 v7 步骤：`if version < 7 { FK OFF → apply_step(7) → FK ON → 传播错误 }`。`usage_costs.request_id` 对 `usage_requests` 有 `ON DELETE CASCADE`，重建事实表必须在 FK 关闭时进行；`FK ON` 写在错误传播之前，因此成功与失败路径都会恢复外键，不会留下“检查静默关闭”的连接。
4. 迁移循环测试从 `0..=5` 扩到 `0..=6`，并在循环内用 `apply_step(6, MIGRATION_0006)` 构造真正的 v6 库（防止 v6→v7 重复建表）。
5. 新增测试 `v7_upgrade_keeps_cost_rows_and_a_refused_step_never_advances_the_version`：v6→v7 后费用行逐字保留、`usage_costs` 的外键仍指向 `usage_requests`、`PRAGMA foreign_keys=1`、`foreign_key_check` 0 行；重复 `migrate` 为 no-op 且行数不变；非法步骤 `apply_step(conn, 99, "CREATE TABLE broken (;")` 失败后 `user_version` 仍为 7 且未留下半成品表。
