## 交付内容

| 项 | 内容 |
|---|---|
| `entry_key(namespace, session, message)` | `SHA256` 逐字段 `u32 big-endian 长度 + UTF-8 字节`，域前缀 `wbp-wb-message-v1`，输出 64 位小写 hex |
| `hash_id(value)` | 同一 length-prefix 编码的单值 SHA256，用于 `session_hash`/`message_hash` |
| `MessageIdentity` | `entry_key`/`session_hash`/`message_hash`/`requested_model`/`event_at_ms`/`upstream_model`/`response_model`；**不含原始 session/message id** |
| `Identity` | `Ready` / `Malformed(MalformedReason)` / `Pending` / `InvalidTimestamp` |
| `identify(shell, file_stem, namespace, now_ms)` | 依次校验：session 存在且等于文件 stem → 各 ID 无控制字符且 ≤160 → `messageId` 必需 → 时间戳为非负整数毫秒且不超过 `now + 24h` |
| `MAX_TIMESTAMP_SKEW_MS` | `24h`；`upstream_model` = `responseModelId → model → requestModelId` 首个有效值，`response_model` 仅取显式 `responseModelId` |

去重键只由 **namespace + sessionId + messageId** 决定：`conversationRequestId`、traceId、文件 offset、JSONL 顶层 `id` 都不参与。失败时使用导入时间替代源时间的行为被明确禁止（缺时间戳、非整数、负值、超 24h 全部记 `InvalidTimestamp`）。

## 错误场景证据（真实失败）

`gate.txt` 之前有三轮真实失败：

1. clippy `variant name ends with the enum's name`（`Identity::PendingIdentity`）→ 变体改名为 `Pending`（诊断码 `pending_identity` 保持不变）；同时删除一处 `assert_eq!(…, true)` 的字面布尔断言。
2. 启动自检中的一条断言写错：用 `now_ms = -1` 期望 `InvalidTimestamp`，但 `timestamp=1` 仍在 24h 窗口内（`-1 + 24h > 1`）而返回 `Ready`。改为 `now_ms = 1 - 24h - 1`，使时间戳恰好超出窗口，断言与契约一致。
3. `control_characters_and_overlong_ids_are_malformed_not_truncated` 失败并给出关键诊断：夹具里的 `\u0001` 被**写入成了真实的控制字节**，导致 JSON 本身非法（`Err(JsonSyntax)`）而不是"转义解码后应判 malformed"。修正为字面转义序列 `\u0001`/`\u0002`，使测试真正覆盖"JSON 合法但 ID 含控制字符"的场景。诊断完成后已把测试 helper 的整行回显移除，避免把正文写入日志。
