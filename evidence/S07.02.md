## 交付内容

| 项 | 内容 |
|---|---|
| `RETENTION_DAY_MS` | `86_400_000` |
| `is_expired(event_at_ms, now_ms, retention_days)` | **`retention_days <= 0` 一律返回 `false`**（不限期 = 什么都不算过期）；否则 `event_at_ms < now_ms - days*86400000`（`saturating` 运算，不会溢出） |
| `BatchPolicy` | `settings_revision` + `retention_days` 合并为一个值（顺带把 `commit_batch` 的参数从 8 个降回 7 个，避免 `too_many_arguments`） |
| `CommitReport.excluded_retention` | 新增计数 |
| 保留清理墓碑 | `MaintenanceKind::Retention` → `deleted_retention`（S07.01 故意留空的分支在此接入） |

两条规则：

1. **已入库的过期导入 → `deleted_retention`**：自动保留清理与手动清除走同一条"先落墓碑再删明细"的路径，只是状态不同（`deleted_retention` vs `deleted_manual`），因此两者都可辨识、都永久。
2. **首次过期候选 → `excluded_retention`**：在 `commit_batch` 内、写任何行之前判定；命中则该记录**从不被导入**（`state='excluded_retention'`、无事实行），于是"窗口先缩短再延长"时它仍然只是一个墓碑 —— 重放只会被判为 `duplicates`。
